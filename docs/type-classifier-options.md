# 시험지 유형 판단: 외부 LLM·Jev·로컬 구현 비교

2026-09-24 공식 공개 문서 확인. 실제 API 호출·비용 측정·학생 자료 전송은 하지 않았습니다. 비교 대상은 첫쪽 OCR 이후의 객관식/주관식/혼합/보류 판단이며 OCR·채점 모델 선택과는 별개입니다. 사용자 확정 선택은 없습니다.

## 비용 — 계산 예시, 실측 아님

한 번에 총입력2,000토큰, LLM 과금 출력100토큰, 일반 요금·캐시 없음·재시도 없음·추가 추론 출력 없음으로 가정합니다. 실제 토큰은 업체별로 다르고 시스템 지시·질문도 포함해야 합니다. 이미지 직접 입력·OCR 비용·개발 운영·세금·환율·최소 결제는 제외합니다.

| 비교 모델 | 입력/출력100만토큰 USD | 1회 예시 USD | 1,000회 예시 USD |
|---|---|---|---|
| OpenAI GPT-5 mini | 0.25 / 2 | 0.0007 | 0.70 |
| Claude Haiku4.5 | 1 / 5 | 0.0025 | 2.50 |
| Jev1.13 직접 API | 0.042 / 무료 | 0.000084 | 0.084 |

근거: [OpenAI 모델 가격](https://developers.openai.com/api/docs/models/gpt-5-mini), [Claude 가격](https://platform.claude.com/docs/en/about-claude/pricing), [TypeSafe 모델 문서](https://docs.typesafe.ai/models). 모델명은 가격 비교용 예시이며 최종 추천 엔진·계정 사용 가능 여부 확인 결과가 아닙니다. 첫쪽만 드물게 분류하는 용도에서는 API요금보다 구현·오분류 검토 비용이 더 중요할 수 있다는 판단입니다. 동일 교재·판본의 분류 결과를 로컬 재사용하면 호출을 줄일 수 있습니다.

## 외부 전송·보관·학습 사용은 다름

외부 API는 요청에 넣은 텍스트·이미지가 업체로 전송됩니다. 허용한 처리와 보안 사고로 인한 유출은 다르지만, 기존 외부 송출 없음 조건에는 부합하지 않습니다. 고객 데이터 학습 미사용은 미보관·미전송·유출 가능성0을 뜻하지 않습니다. 업체 간 실제 사고 확률을 공개 정책만으로 순위 매기지 않았습니다.

- OpenAI API: 기본 고객 데이터 학습 미사용, 일반적인 abuse monitoring 로그 최대30일 및 예외. Responses 저장상태·파일 등은 별도 정책이므로 store=false 하나로 무보관을 보장하지 않습니다. ZDR 등은 적격성·설정·기능 조건이 있습니다. [공식 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)
- Claude API: 상용 보관 정책은 입출력을 원칙적으로30일 이내 삭제하되 계약·기능·안전·법적 예외를 명시합니다. ZDR은 별도 약정·기능·모델 조건입니다. 유지한 데이터는 명시 동의 없이 모델 학습에 쓰지 않는다고 설명합니다. 일반 개인용 채팅 구독과 API정책은 구분합니다. [상용 보관](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data), [API/ZDR](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)
- Jev: 공식 문서는 고객 요청·응답으로 학습하지 않는다고 명시합니다. 기업 고객 ZDR별도 제공. 기본 보관 일수를 확인한 공개 문서는 숫자로 고정하지 않고 필요한 기간으로 규정하므로, 일반 계정에0일·30일이라고 단정하지 않습니다. API도 외부 처리이며 판단형이라는 이유로 더 비공개인 것은 아닙니다. [모델](https://docs.typesafe.ai/models), [Legal/ZDR](https://docs.typesafe.ai/legal), [개인정보 정책](https://typesafe.ai/legal/privacy-policy), [DPA](https://typesafe.ai/legal/data-processing)
- 직접 로컬 구현: 모델·추론·로그를 로컬에 두고 외부 API·동기화·진단 업로드를 배제하면 이 기능의 외부 전송 경로를 없앨 수 있습니다. PC악성코드·계정 접근·백업 공유 등 위험까지0이라는 뜻은 아닙니다. 직접 만들더라도 클라우드에서 실행하면 같은 로컬 이점이 생기지 않습니다.

## 기능 적합성과 개발비 판단

외부 LLM은 OCR 텍스트의 다양한 지시문 해석과 설명에 유용할 후보입니다. 실제 한국어 교재 유형 판단 성능은 시험 전이므로 최고 정확도를 단정하지 않습니다. 키 보호·망 장애·재시도·요금 관리가 필요하며 배포 앱에 개발자의 비밀키를 하드코딩하지 않습니다.

Jev는 선택지와 상태를 입력해 Choice 등 구조화 판단을 얻는 방식이라 유형 분류 구조에 맞는 후보입니다. 현재 공식 모델은 텍스트 전용이며 이미지 직접 입력을 지원하지 않습니다. 공식 문서도 영어가 주 학습 언어이고 CJK성능은 동등하지 않아 사용자 자료 시험이 필요하다고 명시합니다. 한국어 지시문·OCR노이즈를 포함한 우리 자료에서 별도 검증해야 합니다. 구조화 출력은 정답 보장과 다릅니다. Jev와 이름이 비슷한 커뮤니티·중계 사이트 대신 TypeSafe직접 문서·단가를 근거로 삼았습니다. 중계 서비스를 쓰면 경유지·비용·정책이 추가됩니다.

직접 만들기는 세 가지를 구분합니다: 로컬 규칙(개발·시험 필요, API비용 없음), 기존 소형 로컬 분류 모델 조정(라벨·실행환경·회귀검증 추가), 범용 판단AI를 처음부터 훈련(현재 좁은 유형 판별 업무에 과도한 범위라는 판단). 구체 시간·총개발비는 산정하지 않았습니다.

## 이 프로젝트에 대한 권고 — 미확정

외부 송출 없음이 유지되면 로컬 규칙+애매한 경우 교사 확인을 우선하고, 부족하면 소형 로컬 분류 모델을 검토합니다. 제한적 외부 처리를 허용한다면 Jev와 소형LLM을 같은 표본으로 비교할 수 있으나 이번 요청은 검토이므로 시험하지 않았습니다.

유형 판별에는 학생 이름·필기·성적이 필요하지 않습니다. 필기 없는 문제 원본에서 지시문·선지 배열 등 최소정보만 로컬 추출해 판단하게 하면 학생 자료 전송을 줄일 수 있습니다. 외부 모델에 보낸 지시문·문제 일부 자체는 여전히 외부로 나갑니다. 분류 결과를 교재·판본별 저장해 같은 시험지의 학생마다 재전송하지 않는 안을 제안합니다. 이 판단 모듈은 앞선 숫자 잘림·서술형 줄 병합을 직접 해결하지 않습니다.
