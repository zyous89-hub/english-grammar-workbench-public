# 범위 축소 판단 — 객관식과 주관식

2026-09-24. 사용자 제공 실무 기준: 객관식50문항 약3분, 주관식50문항 약10분. 사용자 경험에 따른 근사치이며 프로그램과 동일 표본으로 잰 비교 실험은 아닙니다. 스캔·기록 시간이 포함됐는지는 미확인입니다. 문항당 환산은 각각 약3.6초·12초입니다. ‘한 세트’가 항상50문항이라는 뜻은 아닙니다.

## 현 근거에 따른 판단

기한 내 구현 용이성을 우선하면 객관식이 여전히 유리하다는 assistant 판단입니다. 그러나 모든 자유 표기 방식을 자동으로 지원하는 객관식은 쉬운 범위가 아닙니다. 이번 실패는 객관식의 정오답 비교보다 표시 위치·선택/제외 의미 판독에서 발생했습니다. 주관식으로 전환하면 영역 문제 외에 손글씨 전사·오철자 보존·허용 답과 문항 조건의 비교가 추가됩니다.

| 범위 | 장점 | 미해결 과제 | 판단 |
|---|---|---|---|
| 답안 방식/교재 범위를 제한한 객관식 | 최종 결과가 유한한 선택 번호 집합이고 확인된 답은 비교하기 단순 | 답 영역·문항 연결, 숫자 또는 직접 표시 인식 | 기한 내 완성 가능성을 높일 우선 후보 |
| 세 표기 방식을 자유롭게 혼용한 객관식 | 실제 업무 범위를 넓게 수용 | 혼합·제외·취소·수정 충돌과 오검출 | 현재보다 큰 개발/검증 범위. 우선 후보와 같은 난도로 취급하지 않음 |
| 한 단어·짧은 빈칸 주관식 | 긴 문장보다 범위를 좁힐 수 있고 수동 채점 시간 절감 여지 | 필기·철자 오류 보존·밑줄 겹침·부분 글자 누락 | 일반 주관식과 분리해 후속 비교 가능. 현재 더 쉽다는 실측 근거 없음 |
| 문장 작성 주관식 | 수동 채점 부담이 큼 | 여러 줄 추출·문자 누락/대체·복수 허용 답·조건 충족 | 현재 기한 내 완료 후보로는 가장 위험 |

실제 근거: 수동 영역 객관식9개는 assistant 시각 판독과 일치했지만 자동 영역에서는 실패했습니다. 직접 선지 표시8문항은 변화 위치 검출 후 의미 판별에서 막혔습니다. 주관식 문장 표본은 영역을 수동 지정한 뒤에도 문자 누락·대체가 남았습니다. 위 비교는 동등한 대규모 벤치마크가 아니므로 정확도 순위나 성공 확률을 숫자로 만들지 않습니다.

## 실무 가치 판단

후속 사용자 정정으로 속도 중심의 앞선 권고를 수정합니다. **핵심은 반복 채점 피로·고통 감소이며 수동3분을 반드시 이기는 것이 아닙니다.** 더 오래 걸려도 교사가 계속 집중해서 채점하지 않아도 된다면 실무 가치가 있을 수 있습니다. 반대로 빠르더라도 결과를 모두 다시 확인해야 한다면 부담이 줄지 않을 수 있습니다. 기계 무인 대기 시간, 교사 조작/판단 시간, 확인 요청 문항 수·수정 동작·신뢰성·체감 피로를 분리해 평가합니다. 교재 최초 등록 비용과 학생마다 반복되는 비용도 나눠 기록합니다.

주관식은50문항10분으로 절감 여지가 더 크지만 더 쉽게 구현된다는 뜻은 아닙니다. 범용 문장 채점으로 전환하는 것은 이번 기한의 완성 가능성을 높이는 축소로 보기 어렵습니다.

## 권고 — 사용자 최종 범위 확정 전

객관식은 유지하되 세 방식을 한꺼번에 완성하는 대신 한 교재/정해진 표본 범위에서 한 표기 경로를 먼저 끝내고, 별도 학생 자료로 판독·확인 소요 시간을 확인하는 안을 권고합니다. 나머지 경로를 수동 확인으로 넘기는 경우 자동 지원 완료라고 부르지 않습니다. 기존 숫자 경로를 먼저 시험할 근거는 있으나 실제 비중과 검토 부담을 보고 직접 표시 경로의 우선순위를 바꿀 수 있습니다.

답안 위치나 표기 방식을 학생에게 통일시키는 것은 입력 조건 변경입니다. 별도 선택지로 논의할 수 있으나 사용자가 승인한 요구로 취급하지 않습니다. 기존 학생 자료를 처리한다는 조건에서 완성 범위를 제한하는 것과 학생 업무 방식을 바꾸는 것을 구분합니다.

실제50문항 작업으로 반복 판단·검토 부담이 줄어드는지를 보고 범위를 판단합니다. 3분보다 느리다는 이유만으로 중단하지 않습니다. 사용자 요청에 따라 객관식과 주관식의 추가 시험으로 오류·오판정을 확인한 뒤 우선순위를 정하며 최종 범위는 아직 확정하지 않습니다. 해커톤 이후에도 재사용할 코드·시험 자료·실패 기록을 남기는 것을 목표로 합니다. 최초 작성에서는 실행 시험을 하지 않았고 후속 시험은 [추가 비교](verification/2026-09-24-scope-compare.md)에 기록합니다.
