# 대화에서 실제 작업까지 — 기록 예시와 버전 보기

작성일: 2026-09-23. 아래는 실제 대화와 저장된 근거를 엮은 **사후 요약**입니다. 대화 원문이나 앱 성능 시험 결과가 아닙니다.

## 실제 사례: 사용자 요청에 따라 구현을 보류한 과정

| 순서 | 구분 | 실제 내용 | 확인할 근거 |
|---|---|---|---|
| 1 | 최초 사용자 요청 | 기존 이력을 보존해 비공개 저장소에 업로드하고, 원본 스킬을 확인해 첫 구현 단위를 정하도록 요청했습니다 | [대화 003, 메시지 001](conversations/2026-09-23-003.md#001--user) |
| 2 | 실행 절차 | 프로젝트 문서와 Git 이력·인증·동명 원격 유무를 확인했습니다. 조건이 맞아 비공개 원격을 생성하고 기존 2개 커밋을 업로드했습니다 | [Git 확인 기록](verification/2026-09-23-repository.md) |

| 4 | assistant 제안·착수 | 원문 보존·문항 식별·입력 검증·저장/복원 모듈을 제안하고 초안 3개를 작성하기 시작했습니다. 시험·커밋은 하지 않았습니다 | [대화 003, 메시지 005](conversations/2026-09-23-003.md#005--assistant-진행-알림), [결정 D-004](decisions/0004-source-audit-before-implementation.md) |
| 5 | 사용자 범위 변경 | “나중에 알려줄게 일단 프로젝트 내용만 따라잡아봐” | [대화 003, 메시지 006](conversations/2026-09-23-003.md#006--user-질문-응답) |
| 6 | 실제 조치 | 구현을 보류하고 이번 작업에서 새로 만든 초안 3개를 제거했습니다. 기존 파일·Git 이력은 유지하고, 자료 확보 상태·기능 이식표·결정을 문서로 남겼습니다 | [대화 003, 메시지 007~008](conversations/2026-09-23-003.md#007--assistant-진행-알림), [결정 D-004](decisions/0004-source-audit-before-implementation.md) |
| 7 | 검증 | 최종 변경은 문서 13개였고 앱 소스는 포함하지 않았습니다. 변경 형식 검사와 비밀값 패턴 검사를 거쳐 커밋·푸시했습니다. 원격 비공개 여부와 로컬/원격 커밋 일치를 확인했습니다 | 실제 커밋 변경 내용 (비공개 기록) |
| 8 | 결과와 한계 | 프로젝트 파악과 원격 기록은 완료했습니다. 앱·분류 엔진·성능 시험·실행 파일은 없습니다. 삭제한 미커밋 초안은 Git에서 복원할 수 없고, 착수·제거 사실만 문서에 남았습니다 | 그 시점 전체 파일 (비공개 기록) |

즉, 기록은 **사용자 요청 → 조사 → 제안 → 사용자 변경 지시 → 실제 조치 → 검증 → 저장된 버전**을 따라 볼 수 있습니다. GitHub가 대화를 자동 해석해 이 표를 만드는 것은 아닙니다. 작업 시 파일로 기록하고 커밋·업로드한 내용만 남습니다. 미저장 대화나 커밋하지 않은 편집 내용까지 자동 보존되지는 않습니다.

## 현재 선택해서 볼 수 있는 실제 버전

아래 이름은 읽기 편하게 붙인 단계 설명입니다. Git 태그나 출시 버전 이름으로 등록한 것은 아닙니다.

| 단계 | 포함된 내용 | 그때의 전체 파일 | 변경 내용 |
|---|---|---|---|
| 기획 초기 | 요구사항·기록·검증 계획 | 1b23706 전체 보기 (비공개 기록) | 커밋 (비공개 기록) |
| 개발 인수인계 | 인계 문서·시작 지시문 추가 | 2a7404a 전체 보기 (비공개 기록) | 커밋 (비공개 기록) |
| 원본 파악·구현 보류 | 스킬 이식표·원격 검증·범위 변경 기록 | 6b5b085 전체 보기 (비공개 기록) | 커밋 (비공개 기록) |

- 전체 변경 이력 (비공개 기록)
- 인수인계 → 원본 파악 단계 차이 비교 (비공개 기록)

이 문서를 추가하는 커밋은 위 단계 뒤에 이어집니다. 과거 전체 파일 링크는 고정된 커밋을 가리키므로 이후 main 변경에도 그 시점 내용을 보여줍니다. 비공개 저장소이므로 접근 권한이 있는 계정으로 로그인해야 합니다.

## 향후 초기 빌드·후반 빌드를 골라 보려면

2026-09-23 조회 결과 원격 태그 0개, 릴리스 0개입니다. 현재는 기획·문서 버전만 있고 실행 가능한 빌드는 없습니다.

향후 운영 **제안**:

후속 대화에서 버전 자리별 의미를 정했습니다. 이제 [D-005 사용자 지정 규칙](decisions/0005-version-numbering.md)을 적용합니다. 아래 초기/개선 빌드 이름은 설명 예시이며 실제 버전이 아닙니다.

| 저장 방식 | 역할 | 미래 예시 — 아직 없음 |
|---|---|---|
| 커밋 | 작은 변경의 파일·이유·차이를 보존 | 입력 검증 수정 |
| 태그 | 특정 커밋에 고정 버전 이름 부여 | `v0.1.0` 초기 빌드, `v0.2.0` 개선 빌드 |
| 릴리스 | 버전 설명·시험 결과·실행 파일을 함께 제공 | Windows 실행 파일, 사용법, 알려진 제한 |

“당시 코드를 읽기”는 커밋/태그로 가능합니다. “당시 앱을 직접 실행하기”는 그 버전의 실제 빌드 파일을 릴리스에 첨부하거나 당시 환경으로 다시 빌드해야 합니다. 소스 ZIP만으로 실행 파일까지 보관됐다고 할 수 없습니다. 화면 변화도 보고 싶다면 검증 시점의 화면 이미지·동영상을 해당 버전에 연결해야 합니다. 현재는 해당 자료가 없습니다.

각 실제 릴리스에는 원본 커밋, 규칙 버전, 자료 버전, 실행한 시험 결과, 실행 파일·해시, 알려진 미지원 기능을 연결하는 방식을 제안합니다. 버전 번호만 붙여 구현·시험이 완료된 것처럼 표시하지 않습니다. 이번 요청에서는 태그나 릴리스를 새로 만들지 않았습니다.
