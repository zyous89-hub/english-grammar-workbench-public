# 만들 프로그램: 객관식 학생 숙제 채점·기록

상태: **2026-09-26 사용자 확정으로 이번 범위는 M1까지입니다. M2는 제외합니다.** [결정 0013](decisions/0013-m1-only-scope.md)을 이전 M1/M2 범위보다 우선합니다. 개발용 OCR·채점 도구는 시험 중이며 독립 실행 앱은 미구현입니다. 이전 목표 정의의 근거는 [대화 006](conversations/2026-09-23-006.md), 범위 변경 직전 현황은 [대화 113](conversations/2026-09-26-113.md)에 보존합니다.

## 마감

사용자 지정 종료일은 **2026-09-28 오전 (Asia/Seoul)**입니다. 정확한 시각은 미지정입니다. **2026-09-27 오후 앱 개발 시작**을 목표로 그 전에 규칙과 처리 흐름을 정리합니다. 자동 실행 예약이나 전체 완성 보장이 아닙니다. [마감·범위 검토](deadline-and-delivery-plan.md)의 이전 M1/M2 가정은 이번 M1 단독 범위 결정으로 대체합니다.

## 사용 목적과 작업 단위

교사가 하던 학생 숙제 채점을 대신하는 프로그램입니다.

2026-09-24 사용자 정정: 핵심 가치는 교사와 다른 학원 선생님들의 **반복 채점 피로·고통을 줄이는 것**입니다. 수동 채점보다 빠른지만으로 성공·실패를 판단하지 않습니다. 해커톤 결과와 별개로 실제 쓸 수 있는 작업물이 남는 것도 목표입니다. 마감은 제출 시점이며 장기적 작업 가치를 부정하는 기준이 아닙니다. 교사의 확인·수정 부담, 오판정, 자동 처리 범위와 체감 피로를 함께 평가합니다.

**한 세트 = 학생 한 명의 1회분 숙제.**

2026-09-24 사용자가 실무 기준으로 **객관식50문항 약3분, 주관식50문항 약10분**을 제공했습니다. 이는 근사 경험치이며 앱과 동일 자료로 측정한 비교 실험이 아닙니다. 스캔·기록 시간 포함 여부는 미확인이고 한 세트가 항상50문항인 것은 아닙니다. 시간 절감률은 실제 앱+교사 검토 시간을 측정한 뒤 비교합니다. [범위 축소 판단](grading-scope-comparison.md)

## 입력 — 사용자 확정

| 입력 | 내용 |
|---|---|
| 학생 스캔 폴더 | 학생의 숙제를 스캔한 JPG 등 입력 파일들 |
| 답지 파일 | 해당 숙제의 PDF 답지 |
| 원본 파일 | 필기 없는 문제 원본 PDF |

학생 폴더·답지·원본을 사용자가 각각 직접 지정합니다([결정 0012](decisions/0012-explicit-grading-inputs.md)). 같은 PDF에 문제와 답지가 있으면 두 역할로 지정할 수 있습니다. 실제 JPG/PDF 표본으로 개발용 처리를 시험했으며, 앱의 파일 선택 화면과 범용 페이지 연결은 아직 없습니다. 스캔을 미리 텍스트로 바꾸거나 전체 문항에 어법 분류를 붙여 오는 것을 필수 입력으로 바꾸지 않습니다.

독립 실행과 학생 데이터의 외부 송출 없는 처리를 유지합니다. 텍스트 PDF는 직접 추출하고 스캔·사진은 로컬 OCR로 읽은 뒤 문항과 정답을 연결하는 방향입니다. 로컬 OCR 개발 시험은 독립 실행 패키징 완료와 다릅니다. 초기 조사 기록은 [입력·OCR·기록 저장 검토](input-ocr-storage-review.md)와 [D-007](decisions/0007-local-ocr-boundary.md)에 보존합니다.

## 목표 — 현재 범위는 M1만

| 목표 | 해야 할 일 | 남길 결과 |
|---|---|---|
| M1: 객관식 채점·기록 | 독립 실행 앱에서 입력·문항 연결, 학생 답 판독, 답지 비교, 교사 확인·수정, 로컬 저장·재열기·보고서 출력 | 해당 한 세트의 채점 기록과 수정 이력 |

흐름: **학생 스캔 + 원본 + 답지 → 학생 답 판독 → 답지 비교 → 교사 확인·수정 → 로컬 저장·재열기·보고서 출력**.

M1은 기능 목표 이름이며 앱 버전 a.b.c와는 별개입니다. M2(오답 어법 구분·추가 기록)는 이번 범위와 완료 기준에서 제외합니다. 기존 M2 설계 기록은 삭제하지 않으며 다시 착수하려면 별도 범위 결정이 필요합니다. 서술형 채점과 정답·해설 분리, 구김·훼손 보정도 현재 구현 범위에서 보류합니다. 추가 문제 생성·학습 관리·어법 분석지 제작을 추가하지 않습니다.

12번 답지 추출은 현재 확인한 객관식 자료 범위에서 해결 처리했습니다. 새로운 형식·스캔형까지 검증을 마쳤다는 뜻은 아닙니다. 네 단계 중단·사유 기록은 다음 실행부터 적용하기로 합의했으며 코드 반영과 검증은 남아 있습니다. 현재 실행 중인 시험의 코드·입력·판정 기준은 변경하지 않습니다.

## 아직 결정하지 않은 세부사항

후속 출력 방향: 사용자는 추후 편집을 위해 로컬 HTML을 선호했습니다. 앱에서 수정 → 원본 채점 데이터 저장 → HTML 재생성 흐름을 제안했으며, 상세는 [D-008](decisions/0008-editable-local-html.md)을 따릅니다.

- JPG 숙제·PDF 답지의 상세 변형과 객관식 답안 형태, 범용 문제/답지 연결 방법.
- 불명확한 스캔·답지 누락·복수 허용 답의 처리와 교사 확인 방식.
- 기록 항목·내부 저장 형식·화면 구성·HTML 편집/저장 방식의 세부사항.
- ‘외부 프로그램 없이’의 설치·실행 범위와 앱에 포함할 인식 구성요소의 허용 범위.
- 기존 ‘실행 중 AI 없음’ 요구는 철회되지 않았습니다. 스캔/손글씨 인식 방식과 이 조건의 양립 가능성을 따로 확인해야 하며, 로컬 AI/OCR 모델을 임의 도입하거나 전면 자동 채점이 검증됐다고 주장하지 않습니다.

현재는 앱 개발 전 규칙 검토와 개발 도구 검증 단계입니다. 이 범위 변경 자체로 앱 구현에 착수한 것으로 기록하지 않습니다.

## 검토용 기록 구조 제안 — 아직 확정 아님

M1 기록 후보: 세트 식별자, 원본 스캔·인쇄 쪽·문항, 읽은 학생 답, 대응 답지 위치·정답, 판정, 근거, 확인 필요 여부.

과거 M2 기록 후보(이번 범위 제외): 연결된 M1 문항 식별자, 어법 ID·명칭, 분류 근거, 분류 상태, 교사 수정 이력.

읽지 못한 답안을 자동 오답 처리하지 않고 판독 보류를 별도로 두는 방식을 제안합니다. 한 문항의 기록을 기준으로 요약과 통계를 계산하여 누락·중복을 확인합니다. 세부 항목은 실제 표본과 사용자 검토 후 확정합니다.
