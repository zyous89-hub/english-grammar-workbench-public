# 포트폴리오 구성안

## 목적

GitHub 저장소 자체를 제출 형식으로 가정하지 않습니다. 심사자가 저장소 전체를 읽거나 실행 파일을 실행하지 않아도 이해할 수 있는 요약 파일을 중심으로 하고, 저장소와 실행 결과는 근거로 연결합니다.

## 추천 읽기 순서

1. 문제, 제약, 목표를 한눈에 보여주는 요약.
2. 실제 입력/분류/교사 확인/HTML 출력 화면.
3. 사용자의 판단과 AI 제안의 차이, 채택·기각 이유.
4. 실제 실패 → 수정 → 동일 시험과 새 사례 재검사.
5. 비교 결과와 남은 한계.
6. 해당 코드 버전과 근거 파일 위치.

권장 요약 분량은 6~8쪽이지만 공식 요구가 아닙니다. 첫 버전에서는 주장보다 실제 작동과 검증을 먼저 확보합니다.

## 제출 형식 주의

이전 대화의 공식 FAQ 확인 기록에는 포트폴리오 파일 1개, 50MB 이하, PDF/ZIP/PNG/JPG, URL 단독 제출 불가라고 되어 있습니다. 2026-09-23 이번 작업에서는 해당 대회 페이지에 재접속하지 못했으므로 최신 조건으로 재검증하지 못했습니다. 제출 전에 실제 신청 화면/운영 안내를 다시 확인해야 합니다.

제안: 최신 조건을 확인한 뒤, 요약 PDF를 중심으로 제출하거나, 허용된다면 요약·실행 결과·안전한 예시·필요 소스를 하나의 ZIP에 구성합니다. GitHub 링크는 보조 근거이며 클릭이나 실행을 전제로 중요한 내용을 생략하지 않습니다. 외부 링크를 파일에 넣는 것 자체의 허용 여부도 최신 안내를 따릅니다.

## 버전과 접근

제출 순간의 코드 버전/커밋과 실행 파일, 시험 결과의 버전을 맞춥니다. 개발은 계속하더라도 제출 자료가 어떤 상태를 설명하는지 보존합니다. 비공개 저장소는 URL만으로 누구나 열람할 수 없으므로, 공개 검토 또는 별도 안전한 증거 패키지를 준비합니다.

## 입증할 것 / 주장하지 않을 것

AI로 구현을 지원받았어도 사용자가 기준을 정의·검토한 실제 흔적을 보여줍니다. '모든 영어를 이해', '완전 자동', '검증 100%', '본선 보장' 같은 미입증 주장을 넣지 않습니다. 대화량이나 커밋 수를 품질 지표로 삼지 않습니다.
