# 대화 007 — 입력 형식·OCR·기록 보안 검토

- 날짜: 2026-09-23 (Asia/Seoul). 개별 발화 시각 미확인.
- 아래 본문은 원문입니다. 사용자 메시지의 `&#x20;` 표기도 유지합니다. 역할·번호만 추가했습니다.
- 도구 출력·내부 추론·인증정보는 제외합니다. 마지막 완료 답변은 수록하지 않습니다.

## 001 — user

학생 숙제(jpg-당장 스캔해서 jpg로 저장하고 있음- 실무가 jpg기준으로 되어있지만 pdf가 더 편하면 바꿔도 됨),&#x20;
답지(pdf - 이건 기본제공형이 pdf인건데 이걸 jpg로 바꿀 필요가 있는지까지 확인)
인식 방법(OCR 혹은 그에 준하는 무언가 개발 가능한지 판단)
기록 양식(구글 docs로 할까 하는데 보안, 데이터 유출 측면으로 다른 더 좋은 대안있는지 확인해서 추천해볼것)

## 002 — assistant (진행 알림)

JPG 숙제와 PDF 답지를 그대로 받을 수 있는지, 인쇄문자·손글씨 인식은 어디까지 가능한지 확인하겠습니다. 기록 방식은 Google Docs와 로컬 저장을 비교해 추천드리겠습니다.

특히 **별도 프로그램을 열지 않아도 되는 것**과 **앱 내부에서도 AI를 쓰지 않는 것**은 다르므로, OCR 방식마다 이 조건을 나눠 검토하겠습니다.

## 003 — assistant (진행 알림)

PDF 처리 스킬도 참고하고 있습니다. 현재 권장은 **숙제는 JPG 그대로, 답지는 PDF 그대로** 받는 방식입니다. PDF 안에 텍스트가 있으면 직접 추출하고, 이미지뿐인 페이지만 앱 내부에서 인식용으로 변환하면 사용자가 파일을 바꿀 필요가 없습니다.

인식의 핵심 난점은 파일 형식보다 **학생 손글씨와 지운 답·화살표·수정 흔적**입니다. 공식 OCR 문서의 지원 범위와 실제 채점에 필요한 판단을 구분해 확인하고 있습니다.

## 004 — assistant (확인 질문)

손글씨 인식에 쓸 OCR도 대부분 학습된 AI 모델입니다. 기존의 ‘AI 없이 실행’ 조건은 어느 범위로 유지할까요?

- 외부 전송·생성형 AI 없이, 앱에 내장된 로컬 OCR은 허용
- 학습된 OCR 모델도 금지하고, 비AI 처리 범위부터 검토

## 005 — user (질문 응답)

OCR이 AI모델인건 몰랐음 - 프로그램형태인줄 알았어. 스탠드얼론 + 외부로 데이터 송출없이 기능하는지?

## 006 — assistant (진행 알림)

네. **OCR을 앱에 포함하고, 학생 자료를 외부로 보내지 않은 채 PC 안에서 처리하는 방식으로 개발할 수 있습니다.** OCR은 프로그램이고, 그 프로그램 안에서 학습된 문자 인식 모델을 사용할 수 있는 구조입니다. 인터넷으로 AI 서비스에 자료를 보내는 방식과는 다릅니다.

모델과 실행에 필요한 파일을 설치본에 포함하면, 설치 후 인터넷을 끊어도 처리하도록 설계할 수 있습니다. 다만 현재 후보가 실제로 외부 통신 없이 작동하는지, 학생 손글씨를 얼마나 정확히 읽는지는 별도로 시험해야 합니다.
