# 대화115 — A 잔류 항목 정정과 B 단계 검토 반영

이 기록은 아래 발화와 제출된 긴 검토 의견의 요약입니다. 원문 인용은 별도로 표시합니다.

사용자 앞선 질문 원문: “A4,A5,A8은 왜 남아있는거야?”

답변 요약: 규칙 질문의 답변 완료와 구현·실험 완료를 혼동해 남겼습니다. A04·A05는 답변 완료 후 설계·구현 후속, A08은 별도 실험 결과 확인으로 이동하는 것이 맞다고 설명했습니다.

사용자는 B 단계의 수치를 9월 28일 제출까지 고정하고 B01·B02·B03·B04·B05·B07을 현행 유지·해결 처리하도록 요청했습니다. B06은 시간이 남을 때만 마지막 문항 하단을 페이지 끝까지 넓히고 6쪽 q39 및 같은 페이지 판정을 확인하는 선택 작업입니다. B08은 이번에 조각을 합치지 않고 서로 다른 답 후보가 4단계·사유 10으로 보류되는지, r 번호를 우선순위로 쓰지 않는지 확인하는 로직 작업입니다.

복수 답 일부 누락으로 오답→정답이 될 수 있으므로 로직 후 134문항 평가에서 B 단계 누락을 우선 조사합니다. 10월에는 무조각 문항·잘린 조각을 세어 B01~B06 원인별로 나눈 뒤 한 수치씩 바꾸며 매번 오답→정답 0건을 확인합니다. [로직]은 일요일 오후 앱 착수 전, [선택]은 시간이 남을 때, [10월]은 제출 후라는 태그를 요청했습니다. 상세 확정 내용은 [결정0014](../decisions/0014-b-stage-freeze.md)에 기록했습니다.

## 반영 내용

- [검토 HTML 115](../ocr-rule-review-115.html): 114의 57개에서 A 3개를 이동하고 B 6개를 해결 처리하여 48개를 남깁니다. 전체 72개 중 제외·이동 24개이며 과거 083·114는 보존합니다.
- B06 [선택], B08 [로직] 상태와 F06·F07의 제출 범위 설명을 수정했습니다. 일반 조각 재결합을 이번 제출 전 필수 작업으로 다시 추가하지 않습니다.
- `docs/ocr-rule-inventory-115.json`에 최신 상태를 저장합니다. 기존 생성기에 스냅샷 렌더 옵션을 추가하여 과거 기준을 다시 생성하지 않고 현재 HTML을 만듭니다.
- 작업 목록·설계도·요구사항·개발 안내와 인수인계에 연결합니다. 10월 작업은 문서에 등록했으며 이번 요청으로 캘린더를 수정하지 않았습니다.

## 확인한 범위

`tests/test_b08_candidate_conflict.py`에서 합성 OCR 출력으로 실제 `grade()`를 실행했습니다. 10개 시나리오에서 서로 다른 번호의 충돌 보류, r 번호·순서·점수 우열 무관성, 동일 집합 중복 처리, 한 조각의 복수 답을 확인했습니다. 작은 답이 아예 없거나 신뢰도 때문에 제외되면 남은 답만 채택될 수 있다는 한계도 확인했습니다. 새 OCR 호출은 없습니다.

현재 결과에는 단계·사유 필드가 없으므로 ‘4단계·사유 10 기록’은 아직 미구현입니다. 합성 검사 통과를 네 단계 중단 구현 완료나 실제 134문항 오답→정답 0건으로 표현하지 않습니다. 이번에 B 수치·문항 경계·OCR 실행 코드·실제 입력·실험 결과를 변경하거나 재채점하지 않았습니다.

HTML은 실제 Chromium에서 48개와 전체 의견, 제거 대상 부재, B06 선택 필터, 구현 확인 필터, 의견 입력·JSON/텍스트 복사·다운로드·새로고침 복원, 데스크톱·390px 모바일 표시를 확인했습니다. 로컬 QA 산출물은 `private/review115-qa/`입니다. 재생성 명령은 `python tools/build_ocr_rule_review.py --snapshot docs/ocr-rule-inventory-115.json --previous docs/ocr-rule-inventory-114.json`입니다.
