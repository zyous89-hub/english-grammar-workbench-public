## assistant — 진행 발화 원문

다른 PC에서 생길 수 있는 설치·메모리·속도 문제와, 이를 줄이는 배포 방식을 확인하겠습니다.

## 실제 조사·설계 제안

[llama.cpp 공식 빌드 문서](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)에서 CPU 및 GPU별 실행 경로와 Windows 아키텍처별 빌드를 확인했습니다. 특정 실행 엔진 채택·배포 시험은 하지 않았습니다.

PC를 바꿀 때 재학습이 필수인 것은 아닙니다. 모델 파일과 호환되는 실행 환경을 배포해야 합니다. RAM 부족, GPU·드라이버 차이, CPU 명령어·OS·아키텍처 차이, 모델 누락, 경로·권한, 속도 및 수치 연산 차이를 검증해야 합니다. 개발PC 성공을 다른 PC의 성공으로 간주하지 않습니다.

제안: 첫 배포 범위를 Windows x64로 제한하고 CPU 실행을 기본 호환 경로로 검증하며 GPU는 선택 가속으로 둡니다. 모델·OCR·실행 엔진·필수 라이브러리를 포함한 오프라인 설치본을 준비하고 새 PC에서 설치·전체 처리 시간·메모리·결과 회귀·통신 차단 실행을 확인합니다. 이는 사용자 확정 사양이 아닌 제안입니다. 지원 최소 RAM/CPU와 처리 시간은 미측정이며 임의 수치를 확정하지 않습니다. 하드웨어가 약하다는 이유로 외부 API에 자동 전송하지 않습니다.

시험지 유형은 동일 교재·판본·원본 및 판별 설정에 묶어 재사용할 수 있다는 제안이며 매 학생마다 분류를 반복하지 않는 방향입니다. OCR 전체 처리 속도는 별도 측정 대상입니다. 모델을 더 작은 것으로 자동 교체하면 결과가 달라질 수 있어 검증 없는 대체는 하지 않습니다. 다른 PC나 깨끗한 설치 환경에서 실제 실행 시험은 아직 하지 않았습니다.
