2026-09-27. 아래 사용자 인용은 이번 요청 원문이며, 구현·응답은 요약입니다. 실제 학생 자료·전사·이미지는 포함하지 않습니다.

## 사용자 요청

> 앱과 채점 로직을 분리한다. 앱은 채점 엔진이 만든 result.json만 읽어서 화면을 그린다.

> 1. result.json 형식을 먼저 정하고 문서로 남긴다. 문항마다 id, 판정(정답/오답/보류), 읽은 답, 답지 정답, 보류 단계, 사유 코드와 한국어 문구, 근거 이미지 목록(이름표 포함), 채점 규칙 버전을 넣는다.
> 2. 앱에는 사유 목록이나 규칙을 직접 넣지 않는다. 사유 문구와 이미지는 결과 파일에 있는 그대로 보여준다.
> 3. 교사 수정은 teacher-corrections.json에 따로 저장한다. 다시 채점해도 교사 값이 우선이고, 새 채점 결과와 다르면 표시만 한다.

> 확인: 결과 파일에 가짜 사유 코드를 하나 추가했을 때 앱을 고치지 않아도 화면에 그대로 뜨는지 테스트한다.

## 구현과 사용자에게 설명한 내용 요약

[계약 v1](../result-format.md)을 먼저 작성했습니다. 제출 ID·실행 ID를 분리하고 같은 제출의 문항 ID에 교사 수정을 연결했습니다. 화면은 답을 채점하지 않으며 교사가 답과 판정을 함께 지정합니다. 엔진은 수정 파일을 쓰지 않습니다.

- `src/result_files.py`: 계약 검증, 원자적 파일 저장, 교사 값 우선 적용, 차이 표시, 오래 열린 화면의 덮어쓰기 거부.
- `tools/export_result.py`: 기존 엔진 결과의 판정·문구·이미지를 계약 형식으로 내보내기. 평가 전사는 내보내지 않습니다.
- `src/result-review.html`, `tools/serve_result_review.py`: 로컬 검증 화면. 사유 코드 해석표·채점·OCR 기능 없이 파일 내용만 표시합니다.
- `tests/test_result_files.py`, `tests/fixtures/result-demo/`: 합성 문항과 계약·저장·서버 검증.
