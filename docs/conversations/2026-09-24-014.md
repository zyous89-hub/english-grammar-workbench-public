# 대화 — 첫 페이지 OCR 이후 유형 판단 주체

2026-09-24. 발화별 시각 미조회.

## user — 원문

판단 방법은 이걸 고민중이야

1. 기본 OCR로 채점할 전체 파일(기본적으로 한 시험지는 쭉 유형이 이어짐)의 첫쪽을 기본 OCR로 읽고 보고하게함
2. 해당 결과물을 ? 가 보고 판단을 함 - 그리고 이번 시험지가 객관식인지 주관식인지를 정해줌
3. 저기에 ?에 누굴 넣어야할까 고민중

## assistant — 제안 요약, 사용자 확정 아님

앱 내부 규칙 기반 유형 판별기가 OCR의 문제 지시문·선지 배열·위치를 조합해 시험지 유형을 제안하고, 정보 부족·충돌·혼합이면 교사 확인으로 보내는 안을 제안했습니다. 단일 숫자·밑줄만으로 판단하지 않습니다. 첫쪽에 예제만 있거나 OCR이 단서를 놓치면 판별 보류가 필요합니다. 한 시험지의 유형이 대체로 이어진다는 사용자 설명을 이용하되 뒤쪽에서 충돌하는 신호가 나오면 확인하는 방안은 assistant 제안입니다.

기존 OCR은 읽기를 맡고 유형 판단은 별도 로컬 프로그램 로직이 맡습니다. 규칙 예시·판별 성능은 구현하거나 검증하지 않았습니다. 사용자 확정·모델 학습·새 시험 실행은 없습니다. 작성 이후 최종 발화는 수록하지 않습니다.
