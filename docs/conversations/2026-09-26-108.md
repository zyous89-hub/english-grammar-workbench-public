# 대화108 — 답지 전용 추출 검사

사용자 요청 원문: “그럼 일단 이따 결과오면 이걸 기준으로 다시 판단하는걸로 하고 / 답지 인식쪽 먼저 해보고 있자”

기존 답지는 로컬 PDF 텍스트층을 읽습니다. 스캔 OCR이 아닙니다. 실행 중인 실험에 영향을 주지 않도록 별도 도구 `tools/audit_answer_key.py`를 추가했고 기존 준비·채점 경로에는 연결하지 않았습니다.

입력: 승인된 `data/ocr-review-C/reference-and-answer-key.pdf`, 실제 PDF 20~25쪽. SHA256 `4fbdc29eb34301015132a8125a9ed0d502d388c9f87ca0f380439480f63946a1`. 사용자 전사 JSON에서는 예상 문항 ID 134개만 가져왔으며 학생 답 내용은 답지 추출에 사용하지 않았습니다.

검사 결과: Pattern 1의 122문항과 Pattern 2의 12문항, 총 134문항. 누락·추가·중복·문항 순서 이상·정답 필드 해석 실패 모두 0. 복수 정답 16문항. 20·23·25쪽을 이미지로 렌더링하여 Pattern 전환, 복수 정답의 사례를 원문 대조했습니다. 134개 정답 전부를 사람이 독립 전사한 검증은 아닙니다.

검사 도구는 문항 ID·답지 페이지·정답·원문을 저장합니다. 설명 문장에서 숫자를 끌어와 답을 보정하지 않습니다. 잘못된 복수 답 꼬리(`①, ?`, `①, ⑥`), 중복 번호, 문항 중복·누락, 빈 텍스트의 자체 검사를 통과했습니다. 텍스트가 없는 PDF는 검사 실패로 표시하며 자동 OCR을 실행하지 않습니다.

지원 범위는 현재 교재의 Pattern 1/2, 선택적 Part, `번호)` 문항과 쉼표 구분 1~5/①~⑤ 답 형식입니다. 범용 교재 레이아웃·스캔형 답지 OCR은 미구현이며 다른 배치에서의 정확도는 미검증입니다. 판독 가능하다는 검사는 교재 내용 자체의 정답성이나 올바른 문제지 연결까지 보장하지 않습니다.

재현:

```powershell
private/paddle-env/Scripts/python.exe -m tools.audit_answer_key --check
private/paddle-env/Scripts/python.exe -m tools.audit_answer_key --pdf data/ocr-review-C/reference-and-answer-key.pdf --first-page 20 --question-ids private/answer-key108-input/ids.json --output private/answer-key108-new
```

`--question-ids`는 예상 문항 ID 문자열의 JSON 배열입니다. 기존 출력 폴더는 덮어쓰지 않습니다. 이번 결과는 `private/answer-key108/audit.json` 및 `report.md`입니다. 실행 중인 101의 코드·입력·결과·평가 기준은 변경하지 않았습니다. 결과가 오면 107의 네 단계 분류를 기준으로 재검토합니다.
