# 대화110 — 추가 답지 두 파일 시험

사용자 요청: 바탕화면의 `답지1.pdf`, `답지2.pdf`에 대해 “일단 2개만 시켜봐”. 두 파일은 시험 입력으로만 로컬에서 사용했으며 Git에 포함하지 않았습니다.

| 파일 | 쪽 | 전체 문항 | 숫자 정답 | 서술·수정형 |
|---|---:|---:|---:|---:|
| 답지1 | 12 | 174 | 169 | 5 |
| 답지2 | 1 | 20 | 16 | 4 |

모두 PDF 텍스트층이 있습니다. 기존 108의 Pattern 전용 추출기를 그대로 적용한 결과는 두 파일 모두 0문항/Pattern 제목 없음입니다. 따라서 기존 구현이 다른 객관식 답지를 그대로 지원한다는 결론은 틀립니다. 이번 자료를 보고 새 형식 지원을 추가한 개발 검증이며 독립 평가가 아닙니다.

`tools/audit_numbered_answer_key.py`를 별도 추가했습니다. `explained`는 ‘번호 번 - 원문자 정답 + 해설’, `compact`는 ‘번호) 답’의 전체 필드입니다. 형식을 명시적으로 선택하며 사이트 자동 인식은 아닙니다. 답지2의 확인된 바닥글은 `--footer` 인자로 제외했습니다. 기존 실험 경로에는 연결하지 않았습니다.

전체 13쪽을 렌더링하여 각 문항 번호와 정답을 시각 대조했습니다. 185개 숫자 정답 모두 일치, 번호 누락·중복 0건. 답지2의 6·9·11·17번은 서술·수정형으로 원문을 보존했고 네 답의 문구도 대조했습니다. 특히 17번은 ①로 시작하지만 수정 내용이 있으므로 숫자 답 1로 잘라 채택하지 않았습니다.

답지1의 111·112·135·136·140번은 문장형 정답입니다. 숫자로 오채택하지 않고 검토 대상으로 남겼습니다. 원문에는 정답과 해설이 함께 있으므로 순수 정답 필드 자동 분리가 아직 되지 않았습니다. 초기 진행 설명에서 답지1을 객관식이라고 표현했으나 전체 확인으로 이 다섯 문항이 섞인 것을 확인·정정했습니다.

검증: 새 도구의 혼합 서술형, 복수 답, 잘못된 복수 답 꼬리, 문항 누락 자체 검사 통과. 기존 도구도 별도 자체 검사 유지. 시각 확인은 Codex 대조이며 사람의 독립 검수나 출판사 정답의 내용 타당성 검증이 아닙니다. 숫자 정답 일치는 학생 답 인식 성능 또는 스캔형 OCR 성능을 뜻하지 않습니다.

출력은 `private/answer-key110/key1-result/` 및 `key2-result/`의 `report.html`, `result.json`, `visual-review.json`입니다. 입력 해시:

- 답지1: `243ddc1b2110ebf7df85cb68fece3d30f1fb05c2b22dabf86edb69eed317bc14`
- 답지2: `8f7ffb12f958f9fcbe7f16b85a5e9f76fa1d5e7b030494e53f0644b2e62ab6c8`

재현 시 새 출력 폴더 사용:

```powershell
private/paddle-env/Scripts/python.exe -m tools.audit_numbered_answer_key --check
private/paddle-env/Scripts/python.exe -m tools.audit_numbered_answer_key --pdf C:/Users/Home/Desktop/답지1.pdf --layout explained --output private/answer-key110-recheck/key1
private/paddle-env/Scripts/python.exe -m tools.audit_numbered_answer_key --pdf C:/Users/Home/Desktop/답지2.pdf --layout compact --footer "비상동명학원 중등 영어" --output private/answer-key110-recheck/key2
```

진행 중인 학생 OCR 시험 코드·입력·결과·평가 기준은 변경하지 않았습니다.
