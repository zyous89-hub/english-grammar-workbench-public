# 대화151 — 각 단의 최하단 문항 소속 확장

2026-09-27 사용자 원문:

> 최하단은 각 단의 최하단 문제로 자동으로 들어가게 하드코딩해버릴까 함

assistant 안내 요약: 각 페이지의 두 단에서 마지막 문항을 찾아 아래 경계를 페이지 끝까지 확장하고 세 면적 기준의 소속 변화를 확인합니다. 43번만 지정하지 않으며 소속 배정과 답 채택을 구분합니다.

## 구현과 확인

[결정0023](../decisions/0023-column-bottom-ownership.md). 페이지 우선 OCR의 소속 연결 단계에 공통 하단 확장을 적용했습니다. 원본 페이지 높이를 읽으며 기존 질문 데이터는 덮어쓰지 않습니다. `zone_before_bottom_extension`과 실행 정책을 출력에 기록합니다.

147의 같은 OCR 1,053조각·18쪽·134문항으로 기본 방식 및 50%·60%·70%를 각각 새 출력으로 확인했습니다. 각 실행에서 36개 마지막 문항 범위가 확장되고, 15조각의 소속 상태/교차율이 바뀌었습니다. 기존 단일 소속 조각은 모두 불변입니다. OCR 원문·점수·입력 이미지 해시와 공통 OCR 파일 해시도 유지됐습니다.

- 사진 검토상 8문항(6·27·39·43·60·86·117·120번)의 하단 필기 10조각이 해당 문항에 단일 연결됩니다. 기존 개발용 소속 사진 검토에 대조했으며 교사 확정 소속표를 새로 만든 것은 아닙니다.
- 43번의 `C-07-ink0043`·`0044`는 두 조각 모두 교차율 0%에서 100%로 변해 모든 방식에서 43번에 배정됩니다. 같은 답의 중첩 조각입니다.
- 나머지 변경 5조각은 하단 로고/종이 흔적입니다. 50%·60%·70%에서는 모두 마지막 문항에 단일 연결됩니다. 기본 방식에서는 3개 단일 연결·2개 일부 범위 밖 상태입니다. 이들의 기존 OCR은 무결과 2개, `|`/0.587, `!`/0.189, `1`/0.510이며 자동 답 채택 성공으로 세지 않습니다.
- 모든 문항과 교차가 없는 미배정은 20개에서 13개로 줄었습니다. 일부 밖에 있던 조각의 개선과 완전 미배정 감소를 합쳐서 세지 않습니다.

전체 기존 및 추가 검사 53개 통과(`python -m unittest discover -s tests`). 두 단·페이지 구분, 순서 무관, 50:50 중의성, 위/좌우/페이지 밖 불변, 잘못된 범위, 조각이 없는 페이지의 실제 출력까지 확인했습니다. 새 OCR·최종 재채점은 하지 않았습니다. `evaluation.json`의 보류는 어댑터 초기값입니다. 새 소속으로 인한 보류 전파/최종 판정 변화는 아직 검증하지 않았습니다.
