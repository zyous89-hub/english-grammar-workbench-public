# 대화047 — 허용 문자와 학생 답 표시 방식

2026-09-25. 아래는 사용자 요청·응답 방향의 요약이며 개별 발화 시각은 확인하지 않았습니다.

## 사용자 질문 요약

한자 등 시험 답이 될 수 없는 문자를 OCR 결과에서 제외할 수 있는지 질문했습니다. 동그라미 안에 숫자를 쓰는 학생의 표시 방식을 처리 중 파악해 해당 후보에 가중치를 줄 수 있는지, Jev/OpenAI API 같은 판별 모듈 유무로 비교하도록 요청했습니다.

## 확인한 사실

- 현재 객관식 채점 후처리는 0.8 이상이며 허용된 숫자/구분 문자만 있는 후보를 사용합니다. 따라서 한자 후보는 이미 자동 선택 대상에서 제외되지만 원출력 보고서에는 남습니다. OCR 모델 자체의 문자 출력을 제한하는 기능과 다릅니다.
- 설치된 PaddleX CTCLabelDecode는 예측값의 argmax 및 max를 사용합니다. 출력 클래스와 문자 목록의 대응을 유지해야 하므로 학습된 모델의 문자 사전에서 한자 항목만 삭제하는 변경은 적용하지 않습니다.
- TypeSafe 공식 모델 문서를 재확인했습니다. Jev 1.13은 텍스트 전용으로 이미지 직접 입력을 지원하지 않습니다. 원의 존재·위치·숫자 포함 여부는 별도 영상 처리에서 만들어 전달해야 합니다. https://docs.typesafe.ai/models
- OpenAI의 이미지 지원 모델은 이미지 분석이 가능하지만 작은 글씨·정확한 위치·시각 요소 및 정확도에 한계가 명시돼 있습니다. https://developers.openai.com/api/docs/guides/images-vision

## 제안 — 아직 채택·구현·검증되지 않음

문항 유형별 허용 문자를 두고 금지 문자 검출 시 후보 부적합·재인식·보류로 처리합니다. 원출력은 보존하며 문장 중 금지 문자만 삭제해 정답처럼 만들지 않습니다. 영문 전용 모델이나 허용 문자만 선택하는 디코딩도 후속 시험 후보이나, 숫자·정답으로 강제 치환되거나 제한 후 점수가 부풀려지는 위험을 검증해야 합니다.

문자 인식 점수와 최종 답 표시 근거를 별도로 기록합니다. 원본에 없던 필기, 문제와의 거리, 숫자를 둘러싼 새 원/네모, 학생의 반복적 표시 방식, 취소 여부, 다른 후보와의 충돌을 조합해 답 후보 우선순위와 재인식 순서를 정합니다. 원본의 인쇄 ① 등과 구분하고, 한 문항으로 학생 스타일을 확정하거나 모든 문항에 강제하지 않습니다. 원으로 답을 표시한다는 확신이 높아도 원 안의 숫자가 불명확하면 보류입니다. 0.62 점수에 임의 상수를 더해 기존 0.8을 통과시키지 않습니다.

API 없는 영상 처리 규칙으로 시작할 수 있습니다. Jev는 추출된 구조화 단서의 조합 판단, 이미지 지원 OpenAI API는 실제 후보 이미지의 표시·취소 판단을 보조할 수 있습니다. 둘 다 우리 표본 성능은 미측정입니다. API 없이 로컬 처리하면 외부 API 호출비가 없고, Jev는 보낸 단서·텍스트, OpenAI 이미지 방식은 보낸 학생 필기 이미지가 외부로 전달됩니다. 기존 원본만 보내는 유형 분류와 이번 학생 필기 판별을 구분합니다.

권장 시험은 원본과 학생 이미지에서 답 후보를 먼저 정한 뒤, 표시 방식 판단과 숫자 판독을 분리하고 마지막에 답지와 비교하는 방식입니다. 정답 여부를 학생 표시 스타일의 학습 근거로 사용하지 않습니다. 사람이 확인한 최종 선택을 기준으로 잘못 선택한 답을 정답으로 처리하는 사례와 보류 부담을 평가합니다.

이번 작업은 코드·공식 문서 확인과 비교 설명입니다. 모델 학습·API 시험·OCR 재실행·임계값 변경·기존 판정 변경은 하지 않았습니다.
