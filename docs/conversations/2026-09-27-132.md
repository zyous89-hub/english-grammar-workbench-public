# 대화132 — 요구 개수 기반 추가 탐색 구현·시험

사용자 요청 원문: “ㅇㅋ 그렇게 해보자”

직전131에서 설명한 ‘명시된 요구 개수보다 부족하면 문항 내 제한된 추가 OCR, 계속 불일치하면 보류’의 구현 승인으로 진행했습니다. [결정0017](../decisions/0017-bounded-answer-count-search.md)에 실제 한계와 수치를 기록했습니다.

## 실행

130의 동일 공통 OCR 결과를 보존하고, 원본 지시문에서 명시적 개수를 읽었습니다. 134문항 중 10문항에서 ‘정답 2개 또는 3개’를 확인했습니다. 이 중 부족 조건을 충족한 10문항의 일반 필기49조각에 한 번씩 추가 OCR을 실행했습니다. 선택 표시·빈 조각·제외 조각은 재실행하지 않았습니다. 모델·신뢰도 경계는 유지했습니다.

- 추가 OCR: 49회, 순차 실행, 28.149초. 전체134문항 OCR을 다시 실행한 것은 아닙니다.
- 신뢰도 경계를 새로 통과한 일반 숫자 조각2개. 다른 숫자를 새로 추가한 것이 아니라 같은 숫자의 인식 점수가 상승했습니다. 두 문항 모두 요구 개수보다 부족해 보류했습니다.
- F12 사유14가 기록된 문항3개. 나머지 숫자 후보가 없는 문항은 기존 실패 사유를 유지했습니다.
- 같은 추가 결과 파일로 사용자안·제안안을 순차 재채점했습니다. 요구 개수로 답을 채우거나 답지·전사를 활용해 후보를 고르지 않았습니다.

| 조건 | 전사 일치 자동 확정 | 보류 | 자동 확정 오류 |
|---|---:|---:|---:|
| 사용자안 | 11 | 123 | 0 |
| 제안안 | 9 | 125 | 0 |

최종 확정·보류와 확정 답은130의134문항과 양쪽 모두 같습니다. 사용자안 보류 주 단계는 2단계84·3단계36·4단계3, 제안안은84·38·3입니다. 숫자 답 미확정106·108·110·119는 모두 보류입니다. D11 조건부 전체 문항 중단을 새로 발동하지 않았습니다.
