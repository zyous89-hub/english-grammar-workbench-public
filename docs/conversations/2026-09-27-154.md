# 대화154 — 도형·선 확장·크기 변경 제안의 구현 가능성 검토

2026-09-27 사용자 원문(띄어쓰기·줄바꿈만 정리):

> 1. 도형관련 재검토 결정을 위한 규칙
> 1) 읽은 글자의 결과가 '점수와 상관없이' 0일때
> 2) 읽은 글자가 동그라미 혹은 도형(원, 네모등)일때 + 점수가 0.8 미만일때(루프방지용)
>
> 2. 선을 인식하는 경우
> 1) 상하좌우로 20픽셀(수치는 자신없으니 다시 테스트해볼 예정)넓히고 해당 선과 밝기 차이 및 음영차가 거의 안나는(자세한 수치 조정해볼 예정) 부분을 연결된 걸로 판단해서 새로 인식
> 2) 새로 인식한 부분을 다시 png로 저장(임시파일로 쓰고 나중에 다시 지워지도록)
> 3) 그 후 해당 선을 삭제하고 내부를 새로 인식
>
> 3. 크기 변경이 필요한 경우
> 1) 인식이 실패한 손글씨를 찾음
> 2) 해당 손글씨가 8px(수치 변경가능) 이하이면 무시
> 3) 8px을 넘는경우면 비율을 유지하며 높이를 40px로 변경
> 4) 3의 조각에 상하좌우 24픽셀 추가
> 5) 4의 조각을 png로 저장후 다시 읽음
>
> 가능한지 체크

## 검토 결과 — 제안이며 미적용

세 절차 모두 로컬 OCR와 영상 처리 코드로 구현 가능합니다. 외부 전송이나 실행 중 생성형 AI를 필수로 하지 않습니다. 수치의 적절성·인식률 개선은 시험 전이므로 확정하지 않습니다. 이번에는 코드 변경·OCR·재채점·임시파일 삭제를 하지 않았습니다. 최신 실행은153 그대로입니다.

1. `0`은 점수 무관 재검토 조건으로 확장할 수 있습니다. 현재 `eligible`은 낮은 점수 일반 필기만 검사합니다. OCR 문자○/□ 등과 실제 픽셀의 원/네모 검출은 구분해야 합니다. 도형을0·O·다른 문자로 읽거나 무결과가 되는 경우도 있어 문자 조건만 쓰면 놓칠 수 있습니다. 0.8 미만은 재검토 조건이며 루프 차단이 아닙니다. 각 처리 이력과 최대 재시도 제한이 필요합니다. 이는 사용자 원문에 더한 구현 권고이며 아직 채택하지 않았습니다.
2.20픽셀 확장은 원본 정렬 학생 이미지에서 주변을 새로 가져와야 합니다. 잘린 PNG에 흰 여백만 붙여서는 주변 획을 얻을 수 없습니다. 비교용 페이지와 고해상도 OCR 이미지의 좌표 배율을 구분해야 합니다. 확대된 영역에도 원본 인쇄물 비교·삭제/보존 규칙을 적용해야 합니다. 밝기 차이가 작은 이웃 픽셀을 따라 연결 영역을 찾는 처리는 가능합니다. 다만 같은 펜의 답 숫자와 테두리, 다른 답도 같은 밝기이므로 밝기/음영만으로 같은 의미의 선이라고 판단하거나 삭제하면 안 됩니다. 거리·연속성·방향 등으로 연결을 제한하고, 안쪽 글씨를 둘러싼 테두리임을 확인한 경우에만 삭제하는 방향을 제안했습니다. 숫자1·4·7의 획이나 취소선·밑줄은 임의로 지우지 않습니다. 동일 색으로 붙거나 겹친 부분을 해당 정보만으로 완벽히 분리하는 것은 보장할 수 없습니다.
3. 크기 정규화·PNG 저장·추가 OCR은 구현 가능합니다.8픽셀은 여백을 뺀 실제 필기 높이로 해석하는 방안을 제안했으며, 확정되지 않았습니다. 기준 이하라는 이유로 답 자체를 삭제/무응답 처리하지 않고 재시도만 생략하고 기록하는 것이 안전합니다.40픽셀로 맞추면 원래40보다 큰 글씨는 축소됩니다.24픽셀을 흰 여백으로 해석했을 때, 글씨40+위24+아래24=전체88픽셀이 됩니다. 현재 로컬 모델과 전처리는 전체 높이를48픽셀로 정규화하므로 글씨 높이는 약21.8픽셀이 됩니다.40/24의 조합을 검증 없이 확대 개선으로 단정할 수 없습니다. 현재 구현의 내부 재인식 전처리는 밀착 자르기→2배 확대→사방10픽셀 여백으로, 이번 제안과 다릅니다.

20·8·40·24의 숫자는 시험값으로 관리 가능하지만, 각각의 좌표계/단위와 흰 여백 대 주변 재추출 의미부터 구분해야 합니다.20픽셀 이내에서만 한 차례 확장하고 재판독 후 소속을 다시 계산해야 하며, 이미 다른 조각으로 검출된 같은 필기의 중복도 추적해야 합니다. 최대 재시도 이력은 파생 PNG마다 초기화하지 않고 원래 물리 조각에 연결하는 방안을 제안합니다.

임시 PNG는 읽기가 끝난 뒤 지울 수 있습니다. 다만 결과 JSON/검토 HTML이 참조하는 근거 이미지는 별도로 복사·내장한 뒤 임시 작업본만 정리해야 합니다. 기존 원본·근거 이미지 삭제 요청으로 해석하지 않습니다.
