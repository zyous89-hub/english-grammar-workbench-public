# 대화131 — 지시문의 답 개수를 이용한 추가 탐색 가능성

사용자 요청 원문: “문제에 정답2개 이런게 써있으면 범위내에서 계속 찾게하는 로직 넣을 수 있는지?”

## 검토 답변 요약

가능합니다. 원본 지시문의 ‘정답 2개’, ‘두 개를 고르시오’ 등에서 요구 개수를 읽고, 학생 답 후보가 부족하면 같은 문항 범위에서 추가 탐색을 실행하는 구조입니다. 현재 제출 범위의 텍스트층 PDF에서는 코드로 지시문을 읽을 수 있으며 로컬 OCR과 조합해 독립 실행·외부 전송 없는 구현이 가능합니다. ‘모두 고르시오’만 있는 경우에는 정확한 개수를 추정하지 않습니다.

다만 지시문은 요구하는 답 개수이며 학생이 실제로 적은 개수가 아닙니다. 2개가 나올 때까지 반복하거나 낮은 신뢰도의 숫자를 억지로 채택하면 안 됩니다. 2개를 찾았더라도 남은 영역의 세 번째 답·취소 표시를 놓치지 않도록 첫 탐색은 문항 전체를 완료해야 합니다.

제안 흐름은 전체 문항 후보 수집 → 요구 개수와 차이가 있을 때 의심 영역의 자르기·배율 등을 달리한 제한된 추가 OCR → 기존 신뢰도·중복·충돌 검사 → 계속 불일치하면 교사 확인입니다. 같은 이미지·설정의 OCR을 무한 반복하지 않습니다. 추가 실행 상한과 변환은 아직 확정하지 않았습니다.

현재 F12는 요구 개수와 채택 개수가 다르면 사유14로 보류하는 미구현 선택 작업입니다. 재탐색은 그보다 넓은 신규 동작입니다. 또한 현행 B08/F06은 서로 다른 조각의 숫자를 자동 합치지 않고 충돌로 보류하므로, 나뉜 두 답을 자동 합치는 기능은 별도 규칙 검토가 필요합니다. 이번 질문만으로 기존 충돌 규칙을 해제하지 않았습니다.

현재 코드를 확인한 가능성 검토입니다. 코드·채점 결과 변경이나 새 OCR은 실행하지 않았으며 최신 실행은130입니다.
