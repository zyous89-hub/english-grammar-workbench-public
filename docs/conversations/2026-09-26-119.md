# 대화119 — F08(a) 취소와 전반부 9쪽 시뮬레이션

사용자는 F08(a)를 취소하고 F08(b)는 유지하도록 요청했습니다. 36개 설정 전체 대신 기준 설정 하나로 시험지 전반부를 확인하며, 범위 질문에 **전체 시험지의 2~10쪽, 9쪽**을 선택했습니다. 후속으로 **동그라미 안 알파벳 보존 규칙도 적용**하라고 요청했습니다.

최신 규칙은 [결정0016](../decisions/0016-disable-f08a.md)입니다. 목록 117·대화118의 F08(a)는 취소됐습니다. 인쇄 번호 보존과 조각의 선택 표시 검토 분류는 유지하며, 다른 인쇄 번호가 있다는 사실만으로 문항을 보류하지 않습니다.

## 실행 범위와 입력

- 기준 설정 6000 / 0.7 / 3 하나, 인쇄 2~10쪽의 **66문항·581조각**입니다. 준비 코드 071과 저장된 정렬 좌표를 대조했습니다. 새 정렬·구획 변경이나 36설정 반복은 없습니다.
- `4C-letter-exception076`의 ①~⑤·ⓐ~ⓩ 보존 입력을 사용했습니다. 075와 입력 이미지가 바뀐 **26조각은 로컬 OCR을 새로 실행**했습니다. 인식 실행 약 15.68초, 26회 성공입니다.
- 나머지 **555조각은 075 결과를 재사용**했습니다. 입력 이미지·학생 원조각 해시와 답 후보 처리에 영향을 주는 메타데이터가 동일함을 확인했습니다. 원래 빈 입력의 미실행 기록은 그대로 보존합니다.
- 101의 다른 정렬 결과와는 섞지 않았습니다. 같은 071 정렬·구획의 075/076 입력을 비교합니다. 기존 인식 실행기 코드 해시도 075 검증 기록과 일치했습니다.
- 기존 로컬 모델, 한자 차단, Python 연결·DNS 차단을 사용했습니다. 운영체제 전체 무통신을 증명한 것은 아닙니다.

로컬 최종 보고서: `private/stage-classification-front119-alpha/report.html`. 같은 폴더에 전체 분류·요약 JSON이 있습니다. OCR 재사용·신규 실행 내역은 `private/front119-alpha-work/combined-batch/provenance.json`에 보존합니다. 자료·상세 보고서·전사는 Git 제외입니다.

최종 자동 확정은 1·20·62번입니다. 전사와 일치하며 교재 답과도 일치합니다. **14·23·28·41번은 맞게 읽은 후보가 있으나 F08(b) 겹침 조건으로 보류**됩니다. F08(b)를 임의로 완화하지 않았습니다. 보고서의 ‘기존 판정에서 변경’ 필터에 네 문항을 표시합니다.

문항 주 단계: 자동 확정 3 / 2단계 보류 43 / 3단계 보류 20. 조각별 첫 중단 단계: 1단계 105 / 2단계 447 / 3단계 22 / 숫자 후보 7. 문항 단계와 조각 단계를 구별하며, ‘전사 일치’ 표는 최종 자동 확정된 답만 셉니다. 보류된 OCR 문자열도 보존합니다.

이 범위에는 숫자 답 미확정 106·108·110·119번이 없습니다. 전체 자료의 특수 표시 처리가 해결됐다고 결론 내리지 않습니다. D11 조건부·F12 선택 기능은 적용하지 않았습니다. 운영 채점기 통합과 전체 134문항 평가도 남아 있습니다.

## 검증

- 기존 검사와 변경한 회귀 검사 총 25개 통과. 번호가 다르지만 겹치지 않는 조각은 F08로 전파하지 않고, 번호·문자 종류와 무관하게 실제 겹침 조건에 해당하면 F08(b)를 유지하는 것을 확인했습니다.
- 66문항·581조각, 신규 26·재사용 555의 집합과 합계 일치. 076 이미지 및 원조각 해시 검증, 신규 OCR 26개의 실행 기록 확인.
- 알파벳 보존 조각과 F08(b)로 보류된 대표 조각을 직접 확인했습니다. 전체 수동 이미지 검수는 아닙니다.
- 브라우저에서 1개 설정, 기본 보류 63개·전체 66개·자동 3개·변경 4개, 문항 이미지, 페이지 이동, 모바일 가로 넘침 및 실행 오류 없음을 확인했습니다.
- 기존 075·076 데이터와 v2·v3 결과는 변경하지 않았습니다. 분류 도구와 보고서 틀, 회귀 검사, 규칙 기록만 저장소에 반영했습니다.
