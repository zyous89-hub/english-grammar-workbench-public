# 대화103 — 보류 사유보다 먼저 답의 존재 확인

사용자 요청 원문:

> 1번을 해보자
>
> 순서는
>
> 1. 먼저 빈칸인지 아닌지 확인 - 빈칸이면 추가 고민을 할 필요가 없으니 - 오히려 무응답 처리할지 고민을 해야함

사용자 확정 방향: 답의 존재 여부를 먼저 확인합니다. 비어 있다고 확인된 경우 문자 인식·답 후보 충돌 검토로 진행할 필요가 없습니다. 무응답 처리 및 채점 정책은 아직 논의 중입니다.

현재 코드 확인: `extract_added_ink.py`의 `empty`는 원본 겹침 제거와 조각 추출 후 이미지에 255 미만인 픽셀이 있는지만 확인합니다. `run_added_ink_ocr.py`는 이 값이 참이면 해당 조각의 OCR을 건너뜁니다. 이는 문항 전체의 무응답 판정이 아닙니다. 겹침 삭제로 학생 획이 지워지거나 문항 경계 밖 답이 누락된 경우도 있어서 이 값을 무응답으로 승격하면 안 됩니다. 반대로 보존한 인쇄 선지 번호가 있다고 학생 답이 존재하는 것도 아닙니다.

처리 초안:

1. 학생 스캔과 원본을 비교하여 해당 문항에 학생 답 또는 선택 표시가 있는지 먼저 확인합니다. 숫자 필기뿐 아니라 선지 동그라미·체크·모름 표시도 살펴야 합니다. 풀이 메모 존재만으로 답 존재를 확정하지 않습니다.
2. `답 없음 확인`이면 OCR과 답 후보 선택을 건너뛰고 별도 상태로 기록합니다. 이것을 최종 무응답 또는 오답으로 집계하는 정책은 아직 확정하지 않습니다.
3. `답/표시 있음`이면 인식·선택 표시 해석 단계로 진행합니다.
4. `존재 여부 불확실`이면 빈칸으로 확정하지 않고 확인 필요 상태로 남깁니다. 정렬 실패·영역 잘림·희미한 필기 등을 포함합니다.

핵심 구분: OCR 문자열이 비었음, 추출된 조각이 흰색임, 학생이 답을 쓰지 않았음은 서로 다른 사실입니다. 자동으로 답 없음이 확인되는 기준과 정확도는 아직 구현·검증하지 않았습니다.

이번에는 순서와 상태 구분을 기록했습니다. 실행 중인 101의 코드·입력·임계값을 변경하거나 재채점하지 않았습니다.
