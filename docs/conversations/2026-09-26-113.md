# 대화113 — 설계도 대비 완성까지 남은 작업

사용자 요청 원문: “그럼 여기까지 기준으로 완성까지 얼마나 남았는지 (설계도 기준) 확인해보자”

2026-09-26 현재 저장소의 설계 문서와 실제 소스·검증 기록을 대조했습니다. 다른 작업의 101 실험 결과를 기다리거나 분석하지 않았으며 코드를 변경하지 않았습니다. 읽기 전용 보조 검토에서도 앱과 실험 도구, 사유 기록과 표시 판별기를 구분해야 한다는 점을 확인했습니다.

## 현재 범위와 완료 기준

- 당장은 객관식 우선. 서술형 정답·해설 분리와 채점은 보류합니다. 구김·훼손의 국소 보정과 A07 주관식 밑줄은 10월 후속입니다.
- M1: 파일 선택 → 문항/페이지 연결 → 학생 답 판독 → 답지 비교 → 교사 확인·수정 → 로컬 저장·재열기·보고서 출력까지 하나의 독립 실행 앱에서 처리합니다.
- M2: M1 결과에 연결하여 틀린 어법을 구분·기록합니다. 원래 설계 목표에 남아 있으며 이번 감사에서 임의 제외하지 않습니다.
- 12번 답지 추출은 현재 확인한 객관식 자료 범위에서 해결 처리합니다. 새로운 답지 형식·스캔형까지 무제한 지원이 완료된 것은 아닙니다.
- 다음 실행부터 적용하기로 한 네 단계 중단 및 사유 기록은 합의된 요구입니다. 현재 실행 중인 실험에는 미적용입니다. 1~3단계 실패는 해당 범위의 후속 처리를 중단하며, 다른 답을 무효화할 수 있는 취소 표시 등이 미해결이면 문항 전체 확정도 보류합니다.

## 설계 항목별 실제 상태

| 항목 | 확인된 구현·검증 | 남은 일 |
|---|---|---|
| 파일 입력·자료 연결 | `ocr_source_inputs.py`에 학생 폴더·원본·답지 직접 지정. `prepare_ocr_sources.py`로 정렬·문항 준비 실행 | 앱 파일 선택 화면, 페이지 대응 확인·수정, 교재 전용 파일번호/좌표 설정 의존 해소. 스캔 PDF 일반 입력 미완성 |
| 답지 추출 | 별도 검사 도구 2개. 3개 PDF에서 객관식 319개 원본 대조 일치 | 기존 채점 준비 경로와 통합, 지원 형식 선택·오류 안내. 텍스트 없는 답지 OCR은 미구현 |
| 학생 답 추출·OCR | 로컬 OCR 실행, 정렬·원본 제거·①~⑤/ⓐ~ⓩ 보존, 실제 자료 실험 및 134문항 확인 전사 확보 | 경계 잘림·겹침 획 손실·잔재, 직접 선택·취소·모름 의미, 부분 복수 답 누락. 새 학생·교재에서 독립 검증 |
| 네 단계 판별·중단 | 분류와 사유는 사용자 합의. 기존 코드에 0.8·경로·문자 형식 검사 및 일부 보류 | 각 단계 상태와 사유를 코드에 반영. 빈칸/미인식 구분, 기호 의미 판별, 조각/문항 중단 분리, 문항 번호에 묶인 주석 처리 개선 |
| 채점 | `grade_added_ink.py`가 선택 번호 집합과 교재 답 비교. JSON/SQLite/HTML 산출 | 분리 조각의 복수 답·중복·충돌 통합, 단계 실패 전파, 교사 수정 후 재채점 |
| 화면·기록 | 이미지 비교·검색·페이지 이동용 개발 보고서, 실행별 SQLite 기록 | 교사 답 수정, 변경 이력, 저장 후 재열기, 세트 관리, 결과 HTML 재생성. 규칙 의견 입력 HTML은 채점 수정 앱이 아님 |
| 독립 실행·배포 | 로컬 개발 환경에서 OCR 실행됨 | 설치본·모델/실행환경 포함, 개발 도구 없는 PC 실행, 오프라인·외부 송신 여부·저장 실패 검증. 실행 파일 없음 |
| M2 어법 기록 | 기존 스킬·시작 분류표 조사 및 설계 문서 | 앱 분류 엔진·분류 기준 확정·검수 표본·수정 UI·M1 연결. `rules/`는 안내문뿐 |
| 자료 관리 | 저작권 시험 자료 Git 추적/도달 가능한 과거 이력 제외, 로컬 보존·ignore | 배포본에 시험지·학생 자료·로컬 경로·로그가 섞이지 않는지 최종 검사 |

`src/`는 안내문만 있습니다. `tools/`의 실제 실험 코드와 `tests/`의 추출·입력 검사는 존재하므로 '전부 설계뿐'도 아니지만, 앱이 완성됐다고 볼 수는 없습니다. 제품 목표·backlog·blueprint의 오래된 '표본 없음/미실시' 표시는 당시 기록이며 현재 상태표로 직접 사용하지 않습니다.

## 남은 순서와 조건부 작업량

1. 실행 중인 시험이 끝나면 확인 전사 기준으로 실패 유형·자동 판독 가능 범위를 정합니다. 교재 정답률을 OCR 정확도로 쓰지 않습니다.
2. 기존 근거로 판별 가능한 실패부터 네 단계의 중단·사유 기록을 연결합니다. 의미 판별이 없는 항목은 억지로 분류하지 않고 확인 대상으로 둡니다.
3. 지원 자료 범위 안에서 입력·답지·채점·검토·저장을 한 흐름으로 연결합니다.
4. 설치본을 만들고 개발 환경 없는 PC에서 실제 한 세트 처리·저장·재열기·오프라인 실행을 검증합니다.
5. 별도로 인식 취약 유형 개선과 독립 표본 검증을 계속하고, M1 안정화 후 M2를 연결합니다.

아래는 개발 속도 실측 없이 산정한 **한 명의 집중 개발 시간**입니다. 현재 지원 교재·텍스트 답지·Windows 환경을 사용하고 미해결 표시를 교사가 확인하는 제한된 M1 시제품이라는 조건입니다. 범위 축소 승인이나 납기 약속이 아닙니다.

| 작업 | 계획용 시간 |
|---|---:|
| 기존 실패 근거의 단계별 중단·사유 기록 | 8~16시간 |
| 지원 입력·답지 경로 통합 및 연결 확인 | 4~8시간 |
| 교사 검토·수정·저장·재열기 화면 | 10~20시간 |
| 모델 포함 패키징·통합·오프라인 검증 | 10~20시간 |
| 합계 | 32~64시간 |

하루 집중 작업 6~8시간 기준 약 4~11 작업일에 해당합니다. 자동 기호 판별기 개발, 안정적인 무응답 검출, 분리된 복수 답 통합의 품질 확보, 다양한 교재 자동 매핑, 스캔형 답지 OCR, 인식 모델 추가 학습, 모든 오류 수정, M2, 사용자 검토 대기 시간은 위 합계에 포함하지 않았습니다. 병렬 작업으로 달력 시간이 줄 수 있으나 그대로 나누어 계산할 근거는 없습니다.

전체 설계의 완성 시점은 학생 답 판독 품질·확인 부담과 M2의 분류 범위가 정해지기 전 신뢰할 만하게 확정하기 어렵습니다. 완료율을 임의로 70%/90%처럼 산출하지 않습니다. 사용자 지정 9월 28일 오전까지 M1/M2 전체·일반 배포 완성을 약속할 근거는 없으며, 제한된 시연 흐름도 별도 작업·검증이 필요합니다. 핵심 성공 기준은 자동 처리율만이 아니라 잘못된 확정과 교사의 반복 판단 부담을 줄이는 것입니다.
