## A04 — 번호 모양·크기·단을 이용한 구획

제안한 방식은 로컬 OCR과 일반 코드로 구현 가능합니다. 문항번호 `1.`과 선지 `①`의 모양, 같은 단의 왼쪽 정렬, 글자 크기, 번호 순서를 함께 사용하면 문항 시작을 구분하는 근거가 됩니다. 사용자 자료에서 글자 크기 차이가 항상 성립하는지는 이번에 측정하지 않았습니다. PDF 텍스트층이 있으면 원문 문자/좌표와 제공되는 글꼴 정보를 활용할 수 있습니다. 스캔에서는 OCR 상자의 높이 등으로 시각적 크기를 추정하며, 실제 폰트 크기를 정확히 얻는 것과 다릅니다. OCR이 `①`을 `1`로 읽거나 지문에 `1.` 목록이 있으면 모양만으로 확정할 수 없습니다.

권장 흐름: 원본에서 두 단 구분 → 각 단의 문항번호 후보 검출 → 모양·크기·왼쪽 위치·순서를 함께 검사 → 다음 문항 시작까지 기본 영역 설정 → 정렬한 학생 페이지에 적용 → 영역 밖까지 이어진 필기는 별도 연결/소속 검사. 마지막 문항의 아래는 고정 하단 여백으로 자르지 않고 페이지 끝까지 후보를 보존하는 방향입니다. 공통 지문, 다음 단·다음 페이지로 이어지는 문제, 번호 누락, 윗문항 쪽으로 쓴 답은 별도 취급이 필요합니다. 번호 하나를 놓쳤을 때 두 문제를 합쳐 자동 채점하지 않도록 보류 처리가 필요합니다.

현재 코드도 번호에서 다음 번호까지 기본 상자를 만드는 뼈대는 갖고 있습니다. 크기/모양 결합 판정과 경계 밖 학생 획의 소속 처리는 추가 작업입니다. 문항 상자를 만든다는 것이 전체 상자를 현재의 한 줄용 인식 모델에 그대로 넣는다는 뜻은 아닙니다. 상자는 소속 구분용이며 그 안의 글자 검출/조각 인식은 별도로 수행해야 합니다.

근거: [PaddleOCR 문자 검출 문서](https://paddlepaddle.github.io/PaddleOCR/v3.1.0/en/version3.x/module_usage/text_detection.html)는 글자 위치 상자를 검출한 뒤 인식 모듈에 전달하는 구조를 설명합니다. 제안한 문항 구분 성능 자체를 보증하는 근거는 아닙니다.

## A05 — 전체 페이지 처리의 연산과 오류

먼저 A05는 문항번호 후보의 y 위치만 제한합니다. 이 값만 풀어도 학생 답의 잘림이 해결되지는 않습니다. 학생 후보를 실제로 자르는 것은 A06 문항 영역과 B06 조각 경계입니다. 사용자가 정상 번호는 기존 범위 밖에 없다고 판단한 것과 학생 답을 그 범위로 제한하는 것은 별개입니다.

현행 코드는 SIFT 정렬, 적응형 이진화, 인쇄 마스크, 초기 차이 픽셀과 작은 덩어리 제거까지 이미 페이지 전체에 수행합니다. 따라서 현재 해상도를 유지하면서 가장자리 후보를 살리는 변경이 페이지 전처리 비용을 처음부터 새로 발생시키지는 않습니다. 추가되는 주요 비용은 넓어진 영역의 후보 연결/분류, 추가 조각의 원본 제거와 OCR 호출입니다. 깨끗한 흰 여백은 후보가 적을 수 있지만 오염된 여백은 후보 수를 크게 늘릴 수 있습니다. 정확한 시간·메모리 증가는 측정하지 않았습니다.

| 구분 | 예상 영향 |
|---|---|
| 가장자리까지 학생 필기 후보 탐색 | 여백으로 나간 답을 살릴 수 있음. 초기 전처리는 이미 전체 페이지이므로 추가 비용은 주로 후보 수에 따라 달라짐 |
| 원본/학생의 모든 인쇄 문장까지 OCR | 검출·인식할 글자가 늘고, 원본 제거 전에 처리하면 인쇄 글자와 필기가 섞임 |
| 한 줄 인식 모델에 페이지를 한 장으로 입력 | 여러 줄·두 단의 순서와 글자 축소 문제가 생김. 전체 페이지 검출 후 적절한 단위로 읽는 경로가 필요 |
| 고해상도로 모든 단계 실행 | 픽셀 처리량과 메모리가 증가함. 가로·세로를 각각 두 배로 하면 픽셀 수는 네 배지만 실행시간도 정확히 네 배라는 뜻은 아님 |

늘어날 수 있는 오인식: 테두리·그림자·먼지·스테이플 흔적을 문자로 인식, 지워지지 않은 쪽번호·머리말을 답으로 채택, 이름·메모·채점 표시를 답으로 혼동, 단/문항 사이 필기를 잘못 연결하거나 중복 배정. 반면 제한을 유지하면 실제 답을 잘라내는 누락이 발생합니다.

제안은 ‘번호 탐색 범위’와 ‘학생 필기 탐색 범위’를 분리하는 것입니다. 원본 번호를 찾을 때는 원본 레이아웃 근거를 쓰고, 학생 필기는 페이지 전체에서 후보를 보존합니다. 답이 아닌 후보의 제외와 문항 소속 결정을 뒤에서 수행합니다. 소속 불명인 것은 검토 대상으로 두며 무조건 가장 가까운 번호에 붙이지 않습니다. 이 제안은 아직 구현하거나 성능 검증하지 않았습니다.

## A07 — 주관식에서도 조건 사용 확인

`tools/prepare_ocr_sources.py:44`에서 모든 문항에 `_ {3,}`(실제 정규식은 공백 없는 `_{3,}`) 탐색과 y 차이 5 미만 조건을 적용합니다. `kind!='mc' and h['blanks']` 분기에서는 발견한 밑줄만으로 답 조각을 만듭니다. 밑줄이 하나도 없으면 차이 픽셀의 행 기반 추출로 넘어갑니다.

따라서 짧은 밑줄이 곧바로 문항 전체 제외를 뜻하지는 않습니다. 그러나 같은 문항에 긴 밑줄과 짧은 밑줄이 섞여 있으면 긴 밑줄 분기가 선택되고, 짧은 밑줄이나 다른 위치의 답은 별도 탐색되지 않을 수 있습니다. 그림으로 그린 선, PDF에서 여러 `_`가 아닌 한 문자로 표현된 빈칸도 누락 위험이 있습니다. `_` 개수는 화면에 보이는 선의 길이와 같지 않습니다.

과거 실제 주관식 준비 코드 `private/written-batch-20260924/prepare.py:21`에서도 동일한 `_{3,}` 조건을 확인했습니다. 그 코드는 빈칸이 없을 때 일부 유형을 미지원으로 표시하거나 원문 아래의 차이 행을 찾는 별도 분기가 있어 현재 코드와 완전히 같지는 않습니다. 이번 확인은 소스 코드 검사이며 새 주관식 OCR이나 누락 수 측정은 아닙니다.

주관식 개선 방향은 밑줄을 참고 위치로 사용하되 유일한 추출 조건으로 삼지 않는 것입니다. 단순히 3을 2로 바꾸면 2개짜리는 포함되지만 그림 선·밑줄 밖 답 문제는 남습니다. 객관식 쟁점은 사용자 지시대로 해결 처리하고 주관식은 미해결로 남깁니다.

## A08 — 수치 조정으로 인식률이 오를 수 있는가?

가능성은 있습니다. 학생/원본 정렬이 더 잘 맞으면 인쇄 잔재와 학생 획의 잘못된 삭제가 줄어 OCR 입력이 좋아질 수 있습니다. 하지만 정렬 설정을 바꾼다고 반드시 글자 인식률이 오르지는 않습니다. 잘못된 문항 경계, 원본과 실제로 교차한 획의 삭제, 선택 의미 판독 미구현은 이 세 수치만으로 해결되지 않습니다.

| 값 | 조정 효과와 반대 위험 |
|---|---|
| 특징점 수 6000 | 늘리면 대응 근거가 늘 수 있으나 반복 인쇄 특징과 계산 비용도 늘 수 있음 |
| 매칭 거리 비율 0.7 | 낮추면 더 엄격해져 오매칭을 줄일 수 있지만 유효 짝도 줄어듦. 높이면 더 많은 짝과 오매칭이 함께 들어올 수 있음 |
| RANSAC 오차 3 | 낮추면 정밀한 짝만 인정하지만 실패가 늘 수 있음. 높이면 정상 매칭 수가 늘어도 위치 정밀도가 좋아졌다는 뜻은 아님 |

향후 시험은 현재값을 기준으로 한 번에 하나씩 예를 들어 특징점 3000/6000/9000, 거리 비율 0.6/0.7/0.8, 오차 1.5/3/5를 비교할 수 있습니다. 이 값들은 시험안이며 권장 최적값이나 실행 결과가 아닙니다. 한 번에 전체 조합을 돌리는 것부터 시작할 필요는 없습니다.

판정 지표는 매칭 수/중앙 오차만이 아니라 페이지 여러 위치의 겹침, 인쇄 잔재, 학생 획 보존, 교사 확인 문자와의 일치, 잘못된 답 채택 및 시간이어야 합니다. 높은 OCR 점수나 자동 채점 증가만으로 개선을 선언하지 않습니다. 조정에 쓴 자료와 별도 검증 자료를 구분해야 합니다. 필요하다면 인쇄 영역 전체에 고르게 특징점이 퍼지는지도 확인할 수 있지만 이번 요청에서 새 알고리즘으로 확대하지 않았습니다.
