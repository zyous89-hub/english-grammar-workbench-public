# OCR 오류와 채점 영향 — 논의 초안

날짜: 2026-09-23. 사용자 요청: OCR 글자 인식에서 생길 수 있는 오류 논의. 아래는 위험 분석과 설계 제안이며 실제 숙제 시험 결과·사용자 확정 정책이 아닙니다. 모든 영문 사례는 설명용 가상 예입니다.

## 구분할 오류

| 종류 | 설명용 사례 | 채점 영향 |
|---|---|---|
| 글자 대체·누락·삽입 | 학생 `has` → 인식 `had`, `works`의 s 누락 | 맞은 답을 오답으로 판정하거나 다른 어법 오류로 분류 |
| 띄어쓰기·작은 부호 | `can't`의 아포스트로피 누락, 단어 경계 오인 | 원문과 다른 답으로 비교 |
| 학생 오류의 정상화 | 학생 `gose` → 인식 `goes` | 틀린 답을 정답 처리하여 오류를 놓침 |
| 최종 답 선택 실패 | 지운 `was`와 새로 쓴 `were` 중 이전 답 채택 | 최종 답과 다른 판정 |
| 배치·연결 실패 | 3번 답을 4번에 연결, 화살표 이어쓰기 분리 | 글자는 맞게 읽어도 채점이 틀림 |
| 판독 불가를 무응답으로 오인 | 옅은 연필 답을 빈칸으로 인식 | 프로그램이 못 읽은 것을 학생 무응답으로 처리 |
| 인쇄문과 손글씨 혼합 | 문제의 원래 단어를 학생 수정 답으로 인식 | 학생이 실제 쓴 답이 아닌 내용으로 판정 |
| 답지 인식·추출 오류 | 정답 줄·문항 번호·해설 연결 오류 | 같은 답지를 재사용할 때 여러 세트로 오류 전파 |

스캔 노이즈·기울기·문자 두께·영역 분할·사전 설정 등이 인식에 영향을 준다는 점은 [Tesseract 공식 품질 문서](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)를 확인했습니다. 위 구체적인 학생 답 사례의 발생률이나 특정 엔진 성능을 측정한 것은 아닙니다.

## 핵심 설계 제안

### ‘완성된 문장용이라 오답 추출에 부적합한가?’에 대한 구분

OCR을 논문·고등교육 자료나 완성된 문장 전용이라고 일반화하지 않습니다. 엔진은 단어·숫자·작은 영역 인식도 지원할 수 있습니다. 다만 일부 엔진의 사전·언어 패턴·모델의 학습 특성이 정상적인 표현을 선택하는 쪽으로 작용하면 학생의 실제 오답이 바뀔 위험이 있습니다. Tesseract 공식 문서는 일반 문장에 맞춘 기본 설정과 비사전 단어의 인식을 위한 사전 비활성화 설정을 설명합니다. 모든 OCR이 동일하게 자동 교정한다는 뜻은 아닙니다.

문장이 문법적으로 틀렸다는 사실과 글씨가 시각적으로 모호하다는 사실도 구분합니다. 뚜렷하게 쓰인 비문은 그대로 전사할 수 있으며, 바른 문장도 흐릿하면 오독될 수 있습니다. 채점용 인식의 목표는 ‘의도한 올바른 문장 복원’이 아니라 ‘실제 적힌 문자 보존’입니다. 특정 엔진의 적합성은 오답 철자·어미 누락·비문·수정 흔적이 포함된 실제 표본으로 검증해야 합니다.

1. 원본 이미지의 답안 영역, OCR가 읽은 문자열, 교사 수정 문자열, 최종 판정을 구분해 보관합니다. 원본과 최초 인식 결과를 교사 수정으로 덮어쓰지 않습니다.
2. 학생답 인식 단계에서 정답과 비슷해지도록 문자열을 보정하지 않습니다. 맞춤법·문법 자동 교정을 별도로 붙이지 않습니다. 이 설정만으로 모델의 그럴듯한 오독까지 없어지는 것은 아니므로 원본 대조가 필요합니다.
3. 판독/연결 문제는 정오답 판정과 구분합니다. 확정 무응답과 판독 불가도 분리합니다. 분류가 보류된 것을 학생 어법 오답으로 누적하지 않습니다.
4. 원본 답안 영역·인식 학생답·답지 정답을 나란히 보는 확인 화면을 제안합니다. 전체 페이지를 다시 찾지 않고 수정할 수 있게 합니다.
5. 모든 문항을 재검토해야 하면 시간 절감이 어려우므로 의심 사례를 먼저 모읍니다. 그러나 인식 점수가 높아도 잘못 읽을 수 있으므로 점수를 정답 확률로 표시하거나 높은 점수 문항을 무조건 안전하다고 단정하지 않습니다. 자동 처리 분도 표본 검토합니다.
6. 실제 세트로 기준을 정합니다. 문자 인식 오류율, 틀린 답을 맞게 처리한 건수, 맞은 답을 틀리게 처리한 건수, 확인 필요 비율, 교사 수정 시간과 세트당 전체 시간을 따로 측정합니다.

M1에서 읽은 답이나 판정이 바뀌면 M2에 연결된 어법 기록도 재검토해야 합니다. OCR 오류를 학생의 어법 부족으로 누적하면 안 됩니다.

## Codex에 맡기는 경우와 로컬 OCR 앱의 차이 — 후속 설명

2026-09-23 사용자는 Codex라면 같은 채점을 정확하게 할 수 있을 것 같은데 차이가 어디서 생기는지 질문했습니다. 공개 원문과 시각은 [현재 대화 보완본](conversations/2026-09-23-timestamped-session.md)에 있습니다.

비교 대상은 완성된 로컬 앱이 아니라 아직 제안 단계인 ‘OCR + 채점 규칙’입니다. Codex에서 이미지 이해 모델과 도구를 함께 사용하면 문자 인식 외에 문제 지시·문맥·답지·사용자 설명을 종합하고, 필요하면 확대·부분 확인·재검토를 수행하는 흐름을 만들 수 있습니다. 일반 OCR은 주로 문자와 위치를 추출하며, 그 뒤의 채점·어법 판단·재확인 동작은 별도 구현해야 합니다.

이는 Codex가 항상 더 정확하다는 실험 결과가 아닙니다. 문맥을 종합하는 능력은 장점일 수 있지만, 실제 학생 답을 정상 표현으로 추정하거나 없는 내용을 보충할 위험도 있습니다. OpenAI 공식 문서는 이미지의 작은 글자·회전·공간 관계·정확도 한계를 명시합니다. [이미지 이해 기능과 한계](https://developers.openai.com/api/docs/guides/images-vision)

현재처럼 OpenAI 모델에 이미지를 제공해 판독시키는 방식은 PC 안에서만 인식하는 앱과 데이터 처리 경로가 다릅니다. Codex의 파일/명령 실행 위치와 모델 추론 위치를 혼동하지 않습니다. M1의 외부 송출 없는 배포 목표를 충족하는 엔진·규칙·재검토 흐름은 별도 개발해야 합니다. 개발에 Codex를 사용한다는 사실만으로 완성 앱이 같은 판단 능력을 갖는 것은 아닙니다.

교사가 확인한 동일 표본에서 글자 전사 정확도, 정오답 판정, 확인 필요 비율, 처리·검토 시간을 비교하기 전에는 우열을 확정하지 않습니다. 사용자 자료를 외부 모델로 전송하는 비교 실험은 현재 수행하지 않았으며 별도 범위 확인이 필요합니다.

### 다음 논의 항목

실제 숙제의 답안 형태(숫자/선택 표시, 단어·짧은 구, 문장 서술, 화살표·수정 답)의 비중과 사용자에게 더 부담이 큰 오류를 확인합니다. 아직 표본·수동 채점 시간이 없으므로 자동 처리 기준이나 목표 정확도를 숫자로 확정하지 않습니다.

## 실제 수행

기존 조사 문서와 프로젝트 지침, 공식 OCR 품질 문서를 읽고 위험 유형을 정리했습니다. 새 OCR 실행·앱 구현·정확도 실험은 하지 않았습니다.
