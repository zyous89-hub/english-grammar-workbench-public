# 요구사항과 상태

## 사용자가 명시한 조건

| ID | 조건 | 확인 수준 |
|---|---|---|
| R-001 | 기존 HTML 작성 및 어법 분석·분류 스킬을 앱으로 개발 | 사용자 명시; 스킬 원문 미확보 |
| R-002 | 완성 앱은 AI 없이 독립 실행 | 사용자 명시 |
| R-003 | 문제·정답·어법 해설을 입력 자료로 제공 가능 | 사용자 명시 |
| R-004 | 제공 자료에 어법 분류는 없음 | 사용자 명시 |
| R-005 | 이번 저장 요청부터의 대화를 GitHub 저장소로 기록 | 사용자 요청; 원격 저장 미실시 |
| R-006 | 개발 흐름과 결과물을 해커톤 지원 포트폴리오로 활용 | 사용자 의도 |

## 설계 제안 — 아직 세부 확정 아님

| ID | 제안 |
|---|---|
| P-001 | 해설 기반 규칙 분류, 근거 표시, 충돌·불충분 사례의 확인 요청 |
| P-002 | 교사 수정·확정 후 유형별 HTML 생성 |
| P-003 | 대화 로그 / 설계 결정 / 검증 결과 / 제출 요약의 분리 |
| P-004 | 초기 GitHub 저장소 비공개 운영 |
| P-005 | 첫 입력 형식은 정해진 텍스트/표 구조로 제한 |

## 미정

정확한 기존 분류 체계, 입력 형식과 답지 형태, 문항·선지 식별 구조, 기존 HTML의 필수 동작, 기술 스택, 대상 운영체제, 지원 범위, 분류 성능의 목표값, 실제 사용 가능 자료, 공개 범위, 라이선스.

## 첫 버전 완료 기준 초안

예시 자료를 입력하고, 문항별 분류 근거를 확인하고, 교사가 수정·확정한 후 저장·다시 열기·HTML 출력까지 연결되어야 합니다. 지원하지 않는 해설을 정답처럼 확정하지 않아야 합니다. 인터넷을 끊은 대상 환경에서 동일 흐름을 시험해야 합니다. 평가에는 수동 준비·수정 시간을 포함합니다.

이는 목표이지 현재 구현된 기능이 아닙니다.
