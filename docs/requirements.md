# 요구사항과 상태

현재 제품 목적은 **학생 숙제 채점 프로그램**입니다. [제품 목표](product-goals.md)와 [D-006](decisions/0006-grading-first-milestones.md)이 이전의 HTML 제작 중심 제안보다 우선합니다.

## 사용자가 명시한 조건

2026-09-26 대화082 입력 방식 우선 변경: **학생 스캔 폴더·답지 파일·원본 파일을 각각 사용자가 직접 지정**합니다. 이름 검색으로 원본을 임의 선택하지 않습니다. [결정0012](decisions/0012-explicit-grading-inputs.md). 개발용 직접 입력 경로를 추가했으며 앱 파일 선택 UI/범용 자료 매핑은 미구현입니다.

|---|---|---|
| R-001 | 기존 HTML 작성 및 어법 분석·분류 스킬을 앱으로 개발 | 사용자 명시; 관련 로컬 스킬 2개 열람, 최종 이식 대상 확인 대기 |
| R-002 | 독립 실행; 이전 ‘AI 없음’ 표현의 OCR 적용 범위는 후속 맥락 참조 | D-007: 스탠드얼론·외부 송출 없는 로컬 OCR 가능성 질문, 기술 미선정 |

## 설계 제안 — 아직 세부 확정 아님

| ID | 제안 |
|---|---|
| P-001 | 해설 기반 규칙 분류, 근거 표시, 충돌·불충분 사례의 확인 요청 |
| P-002 | 교사 수정·확정 후 유형별 HTML 생성; 현재 필수 목표로 확정하지 않음 |
| P-003 | 대화 로그 / 설계 결정 / 검증 결과 / 제출 요약의 분리 |
| P-004 | 초기 GitHub 저장소 비공개 운영 |
| P-005 | 과거 텍스트/표 입력 제한 제안은 스캔·답지 폴더 입력 요구로 대체됨 |

## 미정

정확한 기존 분류 체계, 입력 형식과 답지 형태, 문항·선지 식별 구조, 기존 HTML의 필수 동작, 기술 스택, 대상 운영체제, 지원 범위, 분류 성능의 목표값, 실제 사용 가능 자료, 공개 범위, 라이선스.

## M1·M2 완료 기준 초안 — 세부 검증 정책은 제안

M1은 한 세트의 스캔과 해당 답지를 연결하고 채점 결과를 저장·다시 확인할 수 있어야 합니다. M2는 M1의 오답 문항과 연결된 어법 기록을 추가해야 합니다. 판독 불가·답지 연결 실패·분류 보류는 실제 오답과 구분하는 방식을 제안합니다. 외부 프로그램을 별도로 사용하지 않는 전체 흐름과 기존 AI 없는 실행 조건을 검증해야 합니다. 지원 형식·허용 답·기록 방식·시간 측정 범위는 표본 확인 후 정합니다.

이는 목표이지 현재 구현된 기능이 아닙니다.
