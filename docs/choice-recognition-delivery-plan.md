## 결론 — 계획 추정, 성능 보장 아님

## 사용자 참여 가정·구체 작업

1. 현재 보유 자료부터 방식별20~30문항 정도와 대응 원본을 초기 진단 묶음으로 준비하는 안입니다. 이는 학습 충분량이나 검증 완료량이 아닙니다. 서로 다른 학생을 포함하고 부족한 방식은 없는 것으로 기록합니다.
2. 학생이 실제 최종 선택한 번호, 선택/제외/취소 표시, 애매해서 본인도 확정할 수 없는 사례를 구분해 검토합니다. 답지 정답과 별개로 라벨을 만듭니다. 전체 좌표를 교사가 직접 그리게 하지 않고 프로그램이 만든 후보를 수정하는 화면을 우선합니다.
3. 이미 본 자료와 다른 학생·페이지의 평가 묶음을 따로 둡니다. 그 자료를 보고 수정하면 개발 자료로 전환됐음을 기록하고 독립 평가로 재사용하지 않습니다.
4. 실제 숙제 한 세트를 평소 방식으로 처리하는 시간과 프로그램+확인 시간을 각각 측정합니다. 기존 약속대로 사용자 수동 시간은 아직 제공되지 않았으므로 절감률을 만들지 않습니다.

사용자의 핵심 기여는 정답처럼 보이는 것을 알려주는 것이 아니라 실제 선택·표시 의도를 확인하고 빠르게 실패 사례를 분류하는 것입니다. 데이터 준비는 병목을 줄이지만 인식 품질이나 범용성을 보장하지 않습니다.
