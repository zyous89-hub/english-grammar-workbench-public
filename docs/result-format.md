# 채점 엔진과 앱 사이의 파일 계약 v1

2026-09-27 사용자 요청에 따른 기준입니다. **앱은 OCR·채점 모듈을 불러오지 않고 `result.json`과 `teacher-corrections.json`만 읽습니다.** 이미지는 `result.json`이 지정한 파일만 표시합니다. 사유 코드별 해석표나 자동 채점 규칙을 앱에 넣지 않습니다.

## 파일 배치와 식별

```text
한-제출-폴더/
  result.json                 # 엔진 소유, 재채점 때 원자적으로 교체
  teacher-corrections.json    # 앱 소유, 엔진은 절대 쓰거나 초기화하지 않음
  evidence/                  # 엔진이 결과에서 참조하는 이미지
```

- UTF-8 JSON. `schema_version`은 정수 `1`입니다. 모르는 버전은 읽기를 중단하고 기존 파일을 보존합니다. 버전1의 모르는 추가 필드는 허용합니다.
- `assessment_id`는 학생 한 명의 한 번의 제출을 나타내는 불투명 문자열입니다. 같은 제출을 재채점할 때 유지하고, 다른 학생·다른 제출에는 새 ID를 씁니다. 이름이나 파일명으로 자동 추정하지 않습니다.
- `result_id`는 매 채점 실행마다 달라집니다. `id`는 같은 제출의 같은 문항에서 유지합니다. 순서·쪽수·조각 번호를 교사 수정의 연결 키로 쓰지 않습니다. 문항이 제거돼도 그 문항의 수정 기록을 삭제하지 않습니다.
- 날짜는 시간대가 포함된 ISO 8601 문자열입니다. `rules_version`은 엔진이 제공하는 불투명한 규칙 버전 문자열이며 앱은 파싱하지 않습니다. 파일 계약 버전과 채점 규칙 버전은 별개입니다.
- 새 결과를 쓸 때 `assessment_id`가 기존 결과와 다르면 중단합니다. 재채점은 새 `result_id`를 사용하며 교사 수정 파일은 그대로 둡니다.

## result.json

```json
{
  "schema_version": 1,
  "assessment_id": "submission-demo-001",
  "result_id": "run-demo-001",
  "generated_at": "2026-09-27T10:00:00+09:00",
  "title": "객관식 검토 예시",
  "questions": [
    {
      "id": "demo-q1",
      "label": "1쪽 · 1번",
      "judgement": "보류",
      "read_answer": "2",
      "answer_key": "2,3",
      "review_stage": 4,
      "reasons": [
        {
          "code": "EXAMPLE-UNKNOWN",
          "message": "예시: 확인할 표시가 남아 있습니다.",
          "stage": 4
        }
      ],
      "evidence_images": [
        {
          "id": "demo-image-1",
          "label": "학생 원래 문항",
          "path": "evidence/demo.png"
        }
      ],
      "rules_version": "example-rules-1"
    }
  ]
}
```

위 내용은 합성 예시이며 실제 학생의 결과가 아닙니다.

| 필드 | 형식과 의미 |
|---|---|
| `schema_version` | 필수, 정수1 |
| `assessment_id`, `result_id`, `generated_at`, `title` | 필수, 비어 있지 않은 문자열 |
| `questions` | 필수, 문항 배열. `id` 중복 거부, 빈 배열 허용 |
| 문항 `id`, `label`, `rules_version` | 필수, 비어 있지 않은 문자열 |
| `judgement` | 필수, `정답` / `오답` / `보류` 중 하나 |
| `read_answer` | 필수, 문자열 또는 `null`. 읽은 답/후보를 엔진이 표시용으로 제공. `null`은 판독 답 없음이며 무응답 확정이 아님 |
| `answer_key` | 필수, 문자열 또는 `null`. 답지 정답 표시용, 앱은 비교 채점하지 않음 |
| `review_stage` | 필수, 정수1~4 또는 `null`. 단계 없는 사유나 확정 결과에서는 `null` 가능 |
| `reasons` | 필수, 배열. 각 항목 `code`, `message`는 비어 있지 않은 문자열, `stage`는 정수1~4 또는 `null` |
| `evidence_images` | 필수, 이미지 배열. 각 항목 `id`, `label`, `path`는 비어 있지 않은 문자열. 이미지 ID는 문항 안에서 고유 |

보류라면 `reasons`가 하나 이상 있어야 합니다. 확정 결과에서는 엔진이 사유·단계를 비울 수 있습니다. 앱은 코드의 종류, 순서, 메시지에서 새로운 판정을 계산하지 않습니다. `FAKE-999` 같은 처음 보는 코드도 **코드와 한국어 문구를 결과에 적힌 그대로** 표시합니다. 문구·이름표는 HTML로 실행하지 않고 일반 텍스트로 표시합니다.

이미지 `path`는 결과 폴더 안의 상대 경로만 허용합니다. 절대 경로, `..`, 외부 URL, 역슬래시, 결과 폴더 밖으로 이어지는 링크는 거부합니다. PNG/JPEG만 지원합니다. 이미지를 못 읽으면 해당 이름표와 오류를 표시하며 다른 이미지를 대신 보여주지 않습니다. 앱에서 원본 위치나 조각 이름을 추정하지 않습니다.

`read_answer`는 채점 확정과 다릅니다. 예를 들어 `read_answer: "2"`, `judgement: "보류"`가 가능합니다. 앱은 답지가 `"2"`라고 임의로 정답으로 바꾸지 않습니다.

선택 표시 기반 교사 확인용 추천은 `evidence_images`에만 추가할 수 있습니다([EGW4 결정0034](decisions/0034-EGW4-choice-mark-recommendations.md)). 이름표 예시는 `추천 ④ · 선택 표시 기반 · 확인 필요`입니다. `read_answer`, `judgement`, `answer_key`, `reasons`에 추천을 복사하지 않으며 앱은 이름표를 해석해 답이나 교사 입력값을 채우지 않습니다. 기존 자동확정 문항에는 추천 근거를 추가하지 않습니다.

## teacher-corrections.json

```json
{
  "schema_version": 1,
  "assessment_id": "submission-demo-001",
  "corrections": {
    "demo-q1": {
      "read_answer": "2,3",
      "judgement": "정답",
      "note": "교사가 원본을 확인함",
      "updated_at": "2026-09-27T10:05:00+09:00",
      "based_on_result_id": "run-demo-001",
      "based_on_rules_version": "example-rules-1"
    }
  }
}
```

- 파일이 없으면 수정0건으로 읽고, 첫 저장 때 만듭니다. 손상된 파일을 없는 것으로 취급하거나 빈 파일로 덮지 않습니다.
- `assessment_id`가 현재 결과와 다르면 적용·저장을 중단합니다. `corrections`는 문항ID → 수정 객체의 사전입니다. 각 수정은 위 필드를 모두 가집니다.
- 교사는 **읽은 답과 판정을 함께 지정**합니다. 문자열 또는 `null`인 답, 세 가지 판정, 문자열 메모를 저장합니다. 앱이 답지로 교사 판정을 계산하지 않습니다.
- 표시 우선순위는 `교사 수정 > 엔진 결과`입니다. 교사 수정이 있으면 해당 답·판정을 최종 표시하고 엔진 값은 별도로 남깁니다. 엔진의 보류 단계·사유·근거 이미지도 비교용으로 유지합니다.
- 교사의 답 또는 판정이 현재 엔진의 값과 다르면 ‘자동 결과와 다름’을 표시합니다. 재채점 후에도 자동으로 교사 값을 바꾸거나 지우지 않습니다. 규칙 버전만 바뀐 것은 답/판정 충돌로 표시하지 않습니다.
- 답 문자열은 그대로 비교합니다. 숫자 순서를 바꾸거나 답 형식을 해석하는 규칙을 앱에 넣지 않습니다. 교사 입력은 저장할 때 앞뒤 공백만 제거합니다.
- 해당 문항이 새 결과에서 사라져도 수정은 파일에 보존하고 연결되지 않은 수정 수를 표시합니다. 다른 문항에 자동 이동하지 않습니다.
- 저장은 같은 폴더의 임시 파일을 완성한 다음 교체합니다. 다른 창에서 수정 파일이 바뀌었으면 덮어쓰지 않고 다시 불러오도록 알립니다. 실패 시 기존 파일을 보존합니다.

## 병렬 개발의 경계와 완료 확인

- 엔진 담당: 같은 제출·문항ID 유지, 판정/문구/이미지/규칙 버전을 포함한 유효한 결과 생성, 수정 파일에 쓰지 않음.
- 앱 담당: 파일 검증·표시·교사 수정 저장·재열기·차이 표시. OCR, 답 파싱, 사유 코드 해석은 엔진에 맡김.
- 함께 확인: 엔진이 새 `result.json`을 쓰고 앱이 다시 읽으면 연결됩니다. 최종 통합 때 화면 안으로 채점 규칙을 복사하지 않습니다.
- 합성 결과에 기존에 없던 사유 코드를 넣고 화면에서 그대로 보이는지, 교사 수정 저장 후 새 실행 결과로 교체해도 교사 값이 우선인지, 수정 파일의 바이트가 재채점 중 유지되는지 시험합니다.
- 실제 앱 포장·파일 선택·OCR 실행 연결은 이 계약의 검증과 별개의 완료 항목입니다.
