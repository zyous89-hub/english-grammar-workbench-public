# 검증 계획 — M1/M2 실제 자료 시험은 미실시

합성 인쇄체 기본 실행 결과는 [별도 기록](verification/ocr-smoke-2026-09-23/README.md)에 있습니다. 실제 학생 숙제 성능 결과가 아닙니다.

## 실사용 문제 1: 학생 답안 인식 평가

[학생 답안 누락 위험과 시험안](student-answer-detection-risk.md)에 따라 문제 인쇄체와 학생 답안 인식을 따로 집계합니다. 전체 페이지 인식과 사람이 지정한 답안 영역 인식도 분리하여 위치 검출·문자 인식·문항 연결 실패를 확인합니다. OCR 출력 없음만으로 무응답 판정을 하지 않습니다.

## 평가 질문

M1: 학생 한 명의 1회분 숙제 스캔과 해당 답지를 받아, 외부 프로그램 없이 정확하게 채점·기록할 수 있는가?

M2: 그 채점 기록에 연결해 틀린 어법을 구분하고 추가 기록할 수 있는가?

## 측정 대기 사항과 단계별 계획

한 세트 = 학생 한 명의 1회분 숙제입니다. 기존 수동 채점 시간은 사용자가 나중에 명확하게 제공할 예정이며 현재 미제공입니다. 목표 시간·속도 향상률을 임의로 정하지 않습니다.

M1 검증안: 스캔/답지 연결, 학생답 판독, 정오답 일치, 판독 보류, 연결 실패, 누락·중복, 저장·복원, 외부 프로그램 없는 전체 실행을 각각 확인합니다. 채점 기준은 제공 답지와 교사가 확인한 허용 답으로 정합니다. 자동 처리한 비율과 정확도를 함께 기록합니다.

M2 검증안: 확인된 오답에 연결된 분류 근거·교사 기준 분류 일치를 검사합니다. M1 판독/채점 오류가 M2에 전파된 경우와, 올바른 M1 결과에서의 분류 오류를 구분합니다. 기록 필드와 산식은 실자료 확보 후 확정합니다.

시간 측정은 수동 채점 시간의 포함 범위를 먼저 확인하고 같은 범위로 비교합니다. 프로그램 처리 시간과 교사 확인·수정 시간을 구분하고 누락시키지 않습니다. 자료 준비·스캔 시간을 포함할지는 사용자가 제공할 기준에 맞춰 표시합니다.

## M2 분류 방식 비교 제안

- 기준 방식: 단순 키워드 기반 어법 분류 + 같은 HTML 출력 기능.
- 개선 방식: 조건 조합·제외 규칙·근거 표시·확인 필요 처리 + 같은 HTML 출력 기능.
- 업무 시간: 실제 기존 작업 방식과 앱 방식의 입력 준비부터 검토·출력까지. 최초 자료 등록과 재사용을 분리.

## 기준 분류

교사가 실제 분류표에 따라 검토합니다. 해설에 없는 분류의 정답을 AI 제안만으로 확정하지 않습니다. 복수 분류와 판단 불가능한 사례의 처리 원칙을 평가 전에 정합니다.

## 자료 분리

개발용/검증용/최종 평가용을 구분하고, 같은 문항의 변형이나 같은 해설 템플릿이 양쪽에 섞이지 않도록 가능한 단위로 묶습니다. 최종 평가자료를 보고 수정하면 그 자료는 개발에 사용된 것으로 표시합니다. 평가 자료 개수는 실제 확보 자료에 따라 정합니다.

## 측정

| 항목 | 기록할 내용 |
|---|---|
| 단일 분류 일치 | 평가 가능한 기준 분류와 일치한 건수 / 제안한 평가 가능 건수 |
| 제안 비율 | 분류 후보를 낸 항목 수 / 전체 항목 수 |
| 확인 필요 | 근거 부족·규칙 충돌·지원 범위 밖을 나눠 건수 기록 |
| 처리 실패 | 프로그램 오류, 파싱 실패를 의미상 보류와 별도 기록 |
| 다중 분류 | 다중 분류를 채택한 경우에만 기준·계산법을 먼저 고정 |
| 교사 수정 | 분류·위치·원문을 수정한 건수와 시간 |
| 내용 보존 | 원문·정답·해설 누락/변형, 강조 위치 오류 |
| 자료 연결 | 중복 번호, 누락 답지, 선지 연결 오류 |
| 전체 시간 | 준비·입력·실행·수정·검토·저장 포함 |
| 오프라인 | 대상 OS·앱 버전·네트워크 조건·결과 |

분류를 낸 사례만의 정확도와 제안 비율을 같이 보고합니다. 대부분을 보류하고 높은 정확도만 주장하지 않습니다.

## 반례의 종류 — 시험 설계이며 실행 기록 아님

문법 용어가 나오지만 해당 오류가 아니라고 부정하는 해설, 여러 선지를 한꺼번에 설명하는 해설, 복수 어법의 관계를 설명하는 해설, 해설 누락, 중복 문항 번호, 수정 대상이 여러 번 등장하는 원문, HTML 특수문자, 저장 후 복원.

## 결과 파일에 반드시 넣을 정보

실행 시각, 실제 코드 커밋, 규칙 버전, 자료 식별자/분할, 기준 분류 작성·검토자, 명령·환경, 성공/실패 건수, 실패 사례, 수정 전후 동일 시험, 회귀 시험, 알려진 한계.

아직 정해지지 않은 항목은 미정, 실행하지 않은 것은 미실시로 적습니다. 테스트 스크립트가 있다는 사실과 앱 기능이 검증됐다는 사실을 혼동하지 않습니다.
