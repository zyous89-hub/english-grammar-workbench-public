# 두 번째 실제 페이지 OCR 시험

2026-09-24. 사용자가 더 많은 문항이 있는 학생 JPG와 해당 원본 PDF를 제공하여 기존 방식을 시험하도록 요청했습니다. PDF 첫 페이지를 렌더링해 학생 이미지와 같은 인쇄 3쪽임을 확인했습니다. 실제 문제·학생답은 이 공개 가능한 요약에 포함하지 않습니다.

## 수행

기존 밑줄 끝 제한 규칙(왼쪽 여백 4px, 위24px·아래3px, 오른쪽 추가 여백 없음)을 유지했습니다. 새 원본과 학생 스캔의 SIFT/RANSAC homography 정렬을 계산하고, 문항 구간은 원본을 보고 수동 지정했습니다. 구간 내 밑줄은 자동 탐지했습니다. 18문항·83개 답란이 원본에서 확인한 개수와 일치했고 전체 좌표 표시 이미지를 시각 확인했습니다. 범용 자동 문항 분할 구현을 의미하지 않습니다.

기존 로컬 PaddleOCR PP-OCRv5_server_rec, CPU, MKL-DNN 끔, 3배 확대·흰 테두리로 83개를 읽었습니다. 초기화 약1.86초, 답란 인식 44.84초이며 전처리·저장·검토 등 전체 시간은 제외했습니다. 모델을 추가 학습하거나 답지에 맞춰 결과를 교정하지 않았습니다.

## 결과

83개 출력 중 3개는 빈 문자열이었습니다. 해당 입력에는 실제 필기가 있으므로 무응답으로 처리할 수 없습니다. 나머지 80개에도 문자 누락·다른 문자 오인·기호 혼입이 있어 성공 수로 세지 않습니다. 일부 조각에는 윗줄 필기·밑줄이 함께 들어갔습니다. 문항 수가 늘었을 뿐 아니라 페이지 줄 간격이 달라 기존 고정 높이 규칙의 한계가 나타났습니다. 그렇다고 모든 오류의 원인이 영역 높이라고 확정하지 않습니다.

사용자 오류 우선순위에 따라 불확실한 결과를 정답으로 확정하지 않았습니다. 교사 검증 전사·허용 답과 대조한 채점은 하지 않았고 답지는 계속 미열람입니다. OCR 정확도·오답→정답 발생률·학생 점수를 산출하지 않았습니다. 일부 오답 표현을 유지한 사례만으로 전체 오류 보존을 보장하지 않습니다.

실제 입력별 HTML 보고서, 6문항씩 나눈 비교 이미지 3개, 83개 입력 조각과 출력 JSON, 일괄 결과, 정렬·좌표·입력 해시, 코드·로그를 Git 제외 private/page2-ocr-20260924/에 보존했습니다. 세 비교 이미지를 눈으로 확인했습니다. HTML은 모든 입력 이미지를 내장한 로컬 정적 파일이며 외부 스크립트·폰트·서비스를 포함하지 않습니다. 실제 자료는 GitHub에 업로드하지 않았습니다. Python 연결/DNS 감사 훅에서 감지한 연결 시도는 0회이며 OS 수준 통신 검증은 아닙니다.
