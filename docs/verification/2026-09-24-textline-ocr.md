# 윗줄 인쇄 글자 경계 및 밑줄 문자 진단

2026-09-24 실제 수행. [사용자 리뷰](../conversations/2026-09-24-008.md)에 따라 이전 밑줄만 제외하던 규칙을 보완했습니다. 앱 구현이나 독립 평가 결과는 아닙니다.

## 변경과 재시험

정렬된 원본의 두 열에서 어두운 픽셀 행을 묶어 인쇄 줄 경계를 구했습니다. 이전 밑줄 제한에 더해 바로 위 인쇄 줄 아래 2px에서 시작하도록 했습니다. 좌우·아래 경계는 유지했습니다. 문항·열 범위는 이 표본에 지정한 값이므로 범용 자동 분석 구현은 아닙니다.

83칸 중 56칸의 위쪽을 추가로 1~8px 줄였고 같은 로컬 PaddleOCR로 전체를 재인식했습니다. 출력 12개가 변했고 변경하지 않은 27개 입력의 출력은 동일했습니다. 빈 출력 2→0개는 정확도 개선 수치가 아닙니다. 초기화 1.91초, 83칸 인식 45.20초이며 전처리·검토·별도 진단 시간은 제외했습니다.

지정한 1-1~3, 2-1, 3-1~3의 윗줄 인쇄 글자 혼입이 비교 이미지에서 제거됐습니다. 8-3, 10-3, 11-4, 12-4 출력은 유지됐습니다. 11-4는 여전히 오인식이며 문자 검출과 정확한 전사를 구분합니다. 10-3은 유지된 사례이지 직전 변경에 의해 처음 개선됐다는 근거는 없습니다.

2-2에서 위로 수정해 쓴 필기가 새 경계에 잘렸고 4-3도 인식이 악화됐습니다. 모든 칸의 성공이나 실사용 가능을 선언하지 않습니다. 이 표본은 규칙 수정에 사용한 개발 자료이며 독립 평가용이 아닙니다.

## 5-3 밑줄 문자 원인 확인

설치된 PaddleX의 text_recognition/predictor.py와 processors.py를 확인했습니다. 높이 48픽셀로 크기를 조정하고 모델 문자 확률의 최대값을 선택한 뒤 CTC 중복·blank 토큰을 제거해 문자열을 만듭니다. 보고서가 기호를 추가하지 않았으며 밑줄 문자와 CTC blank는 다릅니다.

실제 모델 출력 추적에서 밑줄 기호 선택을 확인했습니다(해당 단계 확률 약0.552; 정확도 확률로 해석하지 않음). 이전 높이에서는 없었고 짧아진 입력에서는 생겼습니다. 짧아진 입력에 잘린 높이만큼 흰 여백을 복원한 시험과 밑줄 영역을 흰색 처리한 별도 시험에서 각각 기호가 사라졌습니다. 입력 크기·밑줄 영향을 시사하지만 신경망 내부 단일 원인을 입증한 것은 아닙니다.

진단용 변형으로 전체 출력을 바꾸지 않았습니다. 밑줄 삭제는 필기 획도 훼손할 수 있어 일괄 적용하지 않았습니다. 본 시험의 해당 기호는 그대로 보존했습니다. 후속 후보는 인쇄 줄 제외 후 전체 높이를 흰 여백으로 유지하는 방법이며 아직 전체 시험하지 않았습니다.
