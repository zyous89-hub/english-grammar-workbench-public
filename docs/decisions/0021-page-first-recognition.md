# 0021 — 페이지 전체 필기 추출·OCR 후 문항 소속 연결

2026-09-27 사용자 요청. [대화145](../conversations/2026-09-27-145.md).

## 사용자 요청과 구현

학생 필기를 먼저 찾고 OCR한 다음 문항 범위를 지정해 읽은 결과를 그 범위에 넣습니다. 새 개발 경로는 `tools/page_first_ocr.py`입니다. 기존 문항별 추출 경로와 동결 결과는 회귀 비교용으로 유지합니다.

1. 저장된 페이지 정렬 정보와 원본을 사용해 페이지 전체의 차이 성분을 찾습니다. B 단계 수치는 유지하지만 문항·단·고정 바깥 여백으로 조각을 자르지 않습니다. 페이지 가장자리는 실제 이미지 한계입니다. 검출 조각 ID는 페이지에 속하며 `question_id`가 없습니다.
2. 기존 인쇄 중첩 삭제·원문자 보존·E02 제외·로컬 OCR을 사용합니다. 하나의 조각을 여러 문항용으로 중복 OCR하지 않습니다. 읽기 전에 문항 답지·전사를 사용하지 않습니다.
3. OCR 결과 저장 후 기존 원본의 문항 범위를 읽습니다. 이번 변경은 원본 문항번호 파서·고정 범위 수치를 새로 조정하거나 자동 학습한 것이 아닙니다.
4. 조각의 검출 잉크 경계 상자와 문항 범위의 공간 관계만으로 연결합니다. OCR 숫자·점수·답지 정답·전사는 문항 선택에 쓰지 않습니다. 원본 페이지 조각 ID·이미지·판독은 보존합니다.

## 잠정 소속 정책 — 구현 선택

소속 판단 기준은 사용자가 세부 지정하지 않았으므로 잘못된 문항에 답을 확정하지 않는 보수적인 시작점을 택했습니다. 잉크 상자 전체가 한 문항 안에 있으면 그 문항에 연결합니다. 여러 문항에 걸치거나 일부가 모든 문항 범위 밖이면 연결 가능한 문항 각각에서 확인하도록 표시하며, 어느 한쪽을 자동 승자로 고르지 않습니다. 이는 여러 조각을 합쳐 답을 만드는 B08 문자 재결합이 아닙니다.

- 사유15: **문항 소속 확인 필요 · 경계 또는 범위 밖 필기**, 3단계. 관련 문항의 다른 숫자 후보가 있어도 자동 확정을 막습니다. E02에서 제외된 조각은 소속 보류를 전파하지 않습니다.
- 기존 판독 실패·신뢰도 부족 사유는 보존하고, 별도로 문항 소속 확인 사유를 붙입니다. F08 예외로 이 사유를 면제하지 않습니다. 고신뢰도 숫자라도 소속이 불명확하면 자동 답 후보로 채택하지 않습니다.
- 어느 범위에도 닿지 않는 조각은 `unassigned.json`으로 보존하고 보고서에 노출합니다. 이를 마지막 문항이나 가까운 문항에 임의 배정하지 않습니다. 이 미배정 묶음을 앱의 일반 작업 흐름에 연결하는 작업은 남았습니다.
- 기존 특수 의미 주석과 위치가 겹치는 새 조각은 주석 검토를 유지합니다. 이미지 해시가 같을 때만 기존 주석을 그대로 이전하며, 다르면 검토 필요 표시로 전달합니다. 문항 ID 특례로 답을 정하지 않습니다.

현재 구현은 저장된 정렬 정보가 있는 객관식 개발 자료용입니다. 새 파일 선택부터의 앱 통합·자동 문항 소속 개선·회색 인쇄물 마스크 개선과 구분합니다. 이번 5·7쪽 시험은 기본 OCR 순서 검증이며, 기존 개수/도형 내부 추가 OCR은 실행하지 않았습니다. 기존 추가 단계의 코드나 정책을 삭제한 것은 아닙니다.

## 개발용 실행

저장소 루트에서 `private/paddle-env/Scripts/python.exe -m` 뒤에 다음 모듈/인자를 사용합니다. 출력은 항상 새 폴더입니다.

```text
tools.page_first_ocr prepare <기존 정렬 source 폴더> <새 inputs 폴더> --pages 5 7
tools.run_added_ink_ocr <inputs> <source> <새 OCR 폴더> <로컬 모델 폴더>
tools.page_first_ocr assign <source> <OCR> <새 assigned 폴더> --annotations <기존 결과 JSON>
```

`assigned/results.json`과 `evaluation.json`을 기존 분류·두 안 비교 도구에 넘깁니다. `evaluation.json`의 초기 전부 보류는 답 없는 연결용 초기값이며 최종 채점 결과가 아닙니다. 최종 결과는 분류·정책 비교 후 내보낸 `result.json`입니다. 앱에는 새 규칙을 넣지 않고 엔진이 사유15의 한국어 문구를 전달합니다.
