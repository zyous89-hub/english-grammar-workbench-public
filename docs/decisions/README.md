# 설계 결정 기록

| 기록 | 상태 | 내용 |
|---|---|---|
| [0001](0001-no-ai-at-runtime.md) | 사용자 요구 | 앱 실행 중 AI 의존 없음 |
| [0002](0002-explanation-based-classification.md) | 입력 조건 확정, 구현안은 제안 | 분류 없는 해설을 활용 |
| [0003](0003-traceable-workflow.md) | 기록 의도 확정, 구조는 제안 | 대화·결정·코드·시험·결과 연결 |
| [0004](0004-source-audit-before-implementation.md) | 사용자 후속 지시 적용 | 원본 확인·이식 제안까지만 기록, 구현 보류 |
| [0005](0005-version-numbering.md) | 사용자 확정: 자리별 의미·계산 단위·하위 초기화 | 큰 변화 a / 자잘한 변화 b / 사용자 리뷰 수정 c |
| [0006](0006-grading-first-milestones.md) | 사용자 확정 | 스캔+답지 폴더, M1 채점·기록, M2 오답 어법 추가 기록 |
| [0007](0007-local-ocr-boundary.md) | 후속 질문에 대한 검토; 기술 미선정 | 스탠드얼론·외부 송출 없음과 내장 로컬 OCR의 구분 |
| [0008](0008-editable-local-html.md) | HTML 선호는 사용자 방향, 편집 흐름은 제안 | 로컬 HTML 보고서와 원본 데이터 기반 수정·재생성 |
| [0009](0009-preserve-student-errors.md) | 사용자 우선순위 확인, 보류 기준은 제안 | 로컬 판독 수준 향상과 학생 오답 보존 |

정정할 때 기존 판단이 처음부터 없었던 것처럼 고치지 않습니다. 민감정보가 아니라면 변경 이유와 새 결정을 기록합니다. 제안은 승인 전까지 제안으로 유지합니다.
