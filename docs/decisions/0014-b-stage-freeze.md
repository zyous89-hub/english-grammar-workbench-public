# D-014 — 제출까지 B 수치 고정, 조각 재결합 보류

상태: 2026-09-26 사용자 확정, 대화117 정정 반영. 2026-09-28(월) 제출까지 적용합니다. 사용자 의견의 요약이며 성능 검증 결과와 구분합니다.

## 확정 범위

B 단계 수치는 바꾸지 않습니다(B06 [선택]만 예외).

- B01·B02·B03·B04·B05·B07은 현행 유지로 해결 처리합니다. Gaussian 범위 31·상수 14, 원본 밝기 195·3×3 확장, 면적 8·높이 3, 5×5 닫기, 면적 35·높이 8·폭 3, 흰 여백 10픽셀을 바꾸지 않습니다.
- B는 OCR에 보낼 사각형의 위치를 정하는 단계입니다. 실제 원본 픽셀 삭제는 C 단계입니다. 일부 답만 빠져도 나머지가 유효 후보로 채택될 수 있으므로 누락이 항상 보류로 이어진다고 가정하지 않습니다.
- [로직]은 앱 착수 전까지(일요일), [선택]은 로직 작업 후 시간이 남을 때만, [10월]은 제출 후 작업을 뜻합니다. 자동 실행·알림 예약을 추가한 것은 아닙니다.

## [로직] B08과 F06·F07

이번 제출 범위에서는 조각 병합·문자 재결합을 구현하지 않습니다. 같은 문항의 유효 후보 집합이 서로 다르면 하나를 선택하거나 합치지 않고 **4단계·사유 10 ‘답 후보 충돌’**로 기록합니다. r 번호 순서나 점수 우열을 답 우선순위로 사용하지 않습니다. 한 조각의 `1,3` 같은 복수 답은 계속 허용합니다. 동일 집합의 중복은 새로운 답 번호를 추가하지 않습니다.

이 결정은 대화105·검토114의 여러 조각 재결합에 관한 일반 구현 계획을 이번 제출 범위에 한해 축소합니다. F06·F07의 최신 설명도 함께 갱신합니다.

확인: 실제 `grade()`를 호출하는 합성 10개 시나리오에서 조각 순서·r 번호·점수 우열과 무관한 충돌 보류, 동일 집합 처리, 한 조각 복수 답 유지를 확인했습니다. 현재는 `보류`만 저장하며 단계·사유 코드 필드는 없습니다. 따라서 B08 검증을 전체 완료 처리하지 않고 사유 기록 구현을 남깁니다. [검사](../../tests/test_b08_candidate_conflict.py).

로직 작업 후 확인 전사 **134문항**을 답지와 별도로 대조해 오답→정답을 확인합니다. 발생하면 B01~B06에서 후보가 누락됐는지 먼저 조사하고, 후속 삭제·OCR·답 선택 원인과 구분합니다. B05에서는 `1,3` 중 작은 `1`만 누락되어 `[3]`으로 채택될 수 있습니다. 합성 검사는 이 선택 구조를 확인했을 뿐 실제 134문항의 발생 건수를 측정한 것이 아닙니다. 목표 0건을 이미 달성한 결과로 표시하지 않습니다.

## [선택] B06

로직 작업 후 시간이 남을 때만 각 단의 마지막 문항 아래 경계를 고정 `y=1738` 대신 페이지 끝으로 바꿉니다. **6쪽만** 다시 실행하여 q39 하단 필기가 포함되고 같은 페이지 다른 문항 판정이 유지되는지 확인합니다. 현재는 경계나 추출 코드를 바꾸지 않았습니다. 원본 인쇄물이 빠져 새 잡음이 적을 것이라는 예상도 그 실행에서 확인합니다.

## [10월] 수치 재검토

확인 전사 134문항에서 실제 답이 있는데 조각이 하나도 없는 문항 수와 답이 잘린 조각 수를 먼저 셉니다. B01~B06의 원인 단계별로 나누고, 원인 확인 후에만 수치를 바꿉니다. 한 번에 하나의 수치만 변경하며 매번 오답→정답 0건을 확인합니다. 특히 실제 답이 `1`인 문항의 무조각 비율을 다른 숫자와 비교하고 차이가 크면 B05 수치를 우선 검토합니다. 경계 밖 필기를 따라 확장하는 일반 처리와 옆 문항 혼입 방지도 이 시점에 검토합니다.

B03 누락이 드물다는 판단, B04의 보류 감소, B06의 적은 새 잡음, B07의 판정에 주는 영향이 거의 없다는 설명은 사용자 검토 의견에 포함된 예상이며 새 실측 결과가 아닙니다. 수치 유지 결정은 그대로 적용하되 ‘항상 보류’나 ‘오류 0건’을 보장하는 근거로 쓰지 않습니다. 기존 10월 캘린더 일정은 이번에 수정하지 않았습니다.
