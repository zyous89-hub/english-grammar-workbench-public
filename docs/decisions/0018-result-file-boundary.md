# 0018 — 앱과 채점 엔진을 결과 파일로 분리

2026-09-27 사용자 확정. [대화136](../conversations/2026-09-27-136.md).

앱과 채점 로직을 병렬로 개발하고 로직 변경 때 화면을 수정하지 않기 위해 [파일 계약 v1](../result-format.md)을 경계로 사용합니다. 이 작업은 계약·엔진 출력·검증용 화면까지이며 완성 앱은 별도입니다.

- 엔진은 `result.json`에 문항 ID, 판정, 읽은 답, 답지 정답, 보류 단계, 사유 코드와 문구, 이름표가 있는 이미지 목록, 규칙 버전을 제공합니다.
- 앱은 결과를 표시하고 교사가 지정한 답·판정을 저장합니다. 사유 목록·답 파싱·채점 규칙을 갖지 않습니다. 처음 보는 코드도 결과의 문구 그대로 표시합니다.
- `teacher-corrections.json`은 앱만 씁니다. 같은 제출·문항 ID에 연결하며 재채점으로 초기화하지 않습니다. 교사 값을 우선 표시하고 새 엔진 결과와 다르면 알립니다.
- 제출 ID와 실행 ID를 구분합니다. 결과 계약 버전과 규칙 버전도 구분합니다. 손상·다른 제출·오래 열린 화면의 저장은 기존 기록을 덮어쓰지 않습니다.
- 최종 통합에서는 이 파일을 주고받습니다. 화면에 엔진 규칙을 복사하는 방식을 택하지 않습니다.

표준 라이브러리 기반 검증 서버와 합성 자료로 경계를 검증합니다. 앱 포장, 입력 선택, OCR 실행 연결, 다른 PC의 독립 실행 검증은 이번 완료 범위에 포함하지 않습니다.
