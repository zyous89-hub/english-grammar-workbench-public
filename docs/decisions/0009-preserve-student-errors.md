# D-009 — 판독 향상과 학생 오답 보존

2026-09-24. 사용자 우선순위 확인, 구체적인 보류·확정 기준은 설계 제안입니다.

## 사용자 의도

사용자는 Codex를 실제 앱에서 쓰겠다는 뜻이 아니라 로컬 프로그램에서 그에 준하는 판독 수준을 얻어야 한다는 뜻이라고 정정했습니다. 지나치게 읽기 어려운 글씨를 억지로 읽다가 학생의 오답을 정답으로 바꾸는 위험이 더 크다고 설명했습니다. 외부 AI 도입 요청이나 모델 채택으로 해석하지 않습니다. Codex의 기존 이미지 판독도 교사 검증 정답이 아니므로 동등 성능 달성의 객관적 기준으로 바로 쓰지 않습니다.

## 적용 방향 — 구현 전

- 스캔 원문을 보존하고 인식 결과를 답지에 맞춰 몰래 수정하지 않습니다.
- 인쇄 글자 제거·영역 조정 같은 영상 처리는 학생이 남긴 실제 글자를 보존하는지 검증합니다.
- 애매한 글씨를 문법적으로 그럴듯한 답으로 확정하지 않고 교사 확인 대상으로 남기는 방안을 적용합니다. 명확히 읽힌 오답은 그대로 채점하고, 판독 보류를 오답·무응답으로 바꾸지 않습니다.
- 답지를 정답 판정에 쓰는 것과 불확실한 학생 필기를 정답으로 유도하는 것은 분리합니다.
- 평가에서는 오답을 정답으로 처리한 경우를 별도 핵심 항목으로 봅니다. 보류율과 교사 검토 시간을 함께 기록하여 전부 보류하는 방식으로 성능을 과장하지 않습니다.

확정 임계값·보류 화면은 미정입니다. 후속 사용자 지시에 따라 오답→정답은 허용하지 않는 요구사항이며, 정답→오답도 궁극적으로 제거할 목표입니다. 인식 점수를 실제 정확도 확률로 취급하지 않습니다. 이번 작업은 원칙 기록이며 새 OCR 실행·성능 검증은 하지 않았습니다.

## 사용자 확정 판정 우선순위 — 후속 구체화

왼쪽은 실제 학생 답의 정오답, 오른쪽은 프로그램의 판정입니다. 실제 정오답의 기준은 제공 답지·허용 답과 교사가 확인한 학생 필기이며 OCR 출력만으로 정하지 않습니다.

| 실제 답 → 프로그램 판정 | 사용자 기준 |
|---|---|
| 오답 → 오답 | 정상 |
| 정답 → 정답 | 정상 |
| 정답 → 오답 | 나쁘지만 상대적으로 감수 가능; 궁극적으로 없애는 것이 목표 |
| 오답 → 정답 | 절대 허용하지 않음 |

이는 사용자 요구의 강도이며 현재 시스템에서 오류가 절대 없음을 검증했다는 뜻은 아닙니다. 검증 중 오답→정답이 1건이라도 확인되면 해당 자동 정답 판정 경로를 통과로 보고하지 않고 수정·재검증 대상으로 기록합니다. 유한 표본에서 0건이라는 결과만으로 미지의 모든 입력에 대해 0건을 보장하지 않습니다.

불확실한 경우 자동 정답 확정을 피하고 판독/판정 보류로 남기는 것은 구현 방향입니다. 보류는 자동 오답으로 계산하지 않습니다. 정답→오답의 허용 수치, 자동 정답 확정 조건, 검토 방식은 아직 정하지 않았습니다. 이번 기록은 정책 구체화이며 OCR·채점 시험을 추가 실행하지 않았습니다.
