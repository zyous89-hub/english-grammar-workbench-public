# D-005: 프로젝트 버전 a.b.c

기록일: 2026-09-23. 근거: [대화 005](../conversations/2026-09-23-005.md).

## 사용자 확정 규칙

| 자리 | 올리는 이유 |
|---|---|
| a | 큰 변화 |
| b | 자잘한 변화 |
| c | assistant가 제출한 결과를 사용자가 리뷰하고, 그 지적을 반영한 수정 |

이는 이 프로젝트의 사용자 지정 규칙입니다. 일반적인 Semantic Versioning의 호환성 기준으로 바꾸어 해석하지 않습니다.

## 이번 질문에 적용한 해석

`0.12.0`을 리뷰하여 지적한 두어 개 항목을 한 번에 고쳐 다시 제출하면 `0.12.1`입니다. 수정 항목 수나 내부 커밋 수가 아니라, 사용자 리뷰를 반영한 제출 결과 단위로 c를 한 번 올립니다. 이후 다시 리뷰받아 고친 결과를 제출하면 `0.12.2`입니다. 이 계산 단위는 이번 질문에 대한 assistant의 운영 해석입니다.

상위 자리를 올리면 하위 자리는 0으로 초기화하는 것을 기본 운영안으로 둡니다: `0.12.2` → 자잘한 새 변화 `0.13.0`, 큰 변화 `1.0.0`. 초기화는 사용자가 별도로 명시한 규칙이 아닌 assistant의 보완안입니다.

리뷰에서 큰 기능 변경까지 요청한 복합 사례는 자동으로 c에 묻지 않고 변경 범위와 버전 선택 이유를 기록합니다. 큰 변화·자잘한 변화의 세부 경계는 실제 변경 때 설명합니다.

## 저장 원칙

실제 제출 버전은 해당 커밋에 태그로 연결하고, 변경 기록에는 변경 이유·리뷰 지적·반영 항목·실제 검증 결과를 연결합니다. 실행 파일이 있는 경우 릴리스에도 같은 버전을 사용합니다. 작업 중 커밋마다 제출 버전을 올리지는 않습니다.

위 숫자는 설명 예시입니다. 현재 앱 빌드가 없으므로 `0.12.0` 또는 다른 앱 버전·태그를 이번에 생성하지 않았습니다. 기존 문서 커밋에 소급해서 앱 버전을 붙이지 않습니다.
