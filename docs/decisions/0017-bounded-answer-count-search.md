# 0017 — 지시문 요구 개수 검사와 한 차례 추가 탐색

2026-09-27 대화131의 제안에 사용자가 대화132에서 “ㅇㅋ 그렇게 해보자”라고 지시했습니다. 기존 F12 미적용 기록보다 이 실행의 명시적 적용 상태를 우선합니다.

- 원본 PDF에서 추출한 지시문에 명시된 ‘정답 N개’, ‘N개를 고르시오’만 사용합니다. 숫자·한/두/세/네/다섯, 줄바꿈을 지원합니다. ‘모두’만 있거나 모호한 개수·선지 속 숫자는 추정하지 않습니다. 답지와 평가 전사로 개수를 정하지 않습니다.
- 기존 첫 OCR은 문항 전체 조각을 완료합니다. 하나의 유효 후보 집합이 요구 개수보다 작거나 유효 후보가 없을 때 추가 탐색합니다. 개수가 같거나 많으면 추가 실행하지 않습니다. 서로 다른 후보 집합의 충돌, 정렬 실패, 저장된 특수 의미 주석은 그대로 보류하며 추가 탐색하지 않습니다.
- 추가 탐색은 **최대 한 차례**, 기존 문항 범위에 포함된 일반 학생 필기 조각만 처리합니다. 빈 조각·1단계 제외·인쇄 선택 표시 경로는 건드리지 않습니다. 조각 밖으로 확장하지 않습니다. 흰 바깥 여백만 줄이고 모든 비백색 픽셀을 남긴 채 최근접 방식으로 2배 확대하고 흰 여백10을 추가합니다. B/C 단계의 수치·삭제 규칙은 바꾸지 않습니다.
- 새 판독도 기존 숫자 형식과 신뢰도0.8을 통과해야 합니다. 첫 판독이 탈락했고 새 판독이 통과한 경우에만 새 숫자를 후보로 씁니다. 양쪽 유효 판독이 다르면 높은 점수나 요구 개수에 맞는 쪽을 선택하지 않고 ‘답 후보 충돌’로 보류합니다. 기존 원결과·추가 판독·입력 해시를 모두 남깁니다.
- 문항 조각 간 서로 다른 숫자를 합치지 않습니다(B08/F06 유지). 후보가 있어도 요구 개수와 다르면 F12·4단계·사유14 ‘선택 개수 불일치’로 보류합니다. 유효 후보가 아예 없으면 먼저 발생한 기존 인식 실패 사유를 유지합니다. 답 개수가 맞아도 기존 다른 보류 근거는 해제하지 않습니다.
- 개발용 분류에서 `--answer-counts`를 켠 실행과 두 안 비교에 적용합니다. 기존 실행을 소급 변경하지 않습니다. 앱 본체 통합은 미완료입니다.

구현: `tools/answer_count_search.py`, `tools/classify_grid_stages.py`, `tools/compare_f08_circles.py`. 검증: `tests/test_answer_count_search.py`, [실제 실행132](../conversations/2026-09-27-132.md).

한계: 새 조각 검출·문항 경계 확대·복수 조각 합치기는 없습니다. 같은 입력에서 조건을 바꿔 재확인한 결과이며 독립 평가나 신뢰도 보정이 아닙니다. 원하는 개수가 나올 때까지 반복하지 않습니다.
